# Формат проектов EasyBuilder Pro (.cmtp / .emtp): что проверено

Сведения собраны по трём реальным проектам панели cMT и по коду `hub/seed/ebpro-cmtp/ebpcmtp.py`:
- два рабочих проекта, сохранённые EasyBuilder Pro 6.10.02.300 (revision 492; 88 и 90 окон);
- пустой проект панели 1024×600, сохранённый 6.10.02.421 (revision 492, revision_min 493; 67 окон).

«Проверено» — сверено с файлами; «по виду» — догадка по текстам и размерам, её надо подтвердить. Сами проекты в
репозиторий не кладём: они клиентские, а репозиторий публичный. Тесты строят проект из синтетических записей
(`tests/test_hub_seed_ebpro.py`).

## 1. Контейнер

`u32 revision` + версия (строка MFC) + `u32 revision_min` + `u32 длина` + тело в AES-128-ECB (revision ≥ 240; у старых —
открытым текстом). Ключ вшит в EasyBuilder и записан в `ebpcmtp.py`. Файл читается и записывается обратно побайтно
(проверено на всех трёх проектах). У сборки 6.10.02.300 `revision_min` равен `revision`, у 6.10.02.421 он 493. Обе сборки
пишут revision 492, но записывают часть объектов по-разному (раздел 4), поэтому образцы объектов надо брать из проектов
той же сборки.

## 2. Карта тела

Рабочий проект на 88 окон (тело 13,4 МБ):

| Часть | Где | Размер | Что внутри |
|---|---|---|---|
| шапка | 0 … 351 | 351 Б | счётчики; `u32` по смещению 326 — число картинок (321 в одном проекте, 322 в другом) |
| библиотека картинок | 351 … 10 872 622 | 10,87 МБ | 321 файл (257 PNG, 61 BMP, 3 JPEG); запись: маркер `ff`, GUID (16 Б), `u32` длина, данные |
| промежуток | … 10 889 439 | 16,8 КБ | не разобран |
| окна | 10 889 439 … 13 056 754 | 2,17 МБ | 88 окон, 2523 объекта |
| хвост | 13 056 754 … конец | 379 КБ | таблица тегов OPC UA (461 тег), настройки, шрифты |

Пустой проект (тело 8,43 МБ): библиотека 165 картинок (95 BMP, 68 PNG, 2 JPEG, 6,07 МБ — картинки самого EasyBuilder),
промежуток 8,7 КБ, 67 окон (2,14 МБ, 2012 объектов), хвост 206 КБ. Тегов OPC UA нет, устройство одно — «Local HMI».
Окна: системные 0–10, клавиатуры 50–59, ASCII 60–68, учётные записи 70–74, EasyAccess 76–77, заставка 80, QR-код 82,
системные ASCII и цифровые 83–119. Главное окно 10 пустое: одна рамка окна.

Из 461 тега рабочего проекта на экранах используется 65. Таблица тегов лежит в хвосте, имена тегов из окон есть в ней.

## 3. Окна

Запись окна: имя (CString), ширина и высота (`u32`), 10 нулей, `01 00 00 00 00 00`, GUID (16 Б), `u16` длина и имя слоя (UTF-8),
`u32` число объектов, объекты. Номер окна считается по слотам: свободный номер — 4 нулевых байта между окнами, окна 0–9
системные.

**Проверка полноты:** число объектов в заголовке окна должно равняться прочитанному. Во всех трёх проектах это
выполняется для каждого окна (0 расхождений). До исправления короткого заголовка (раздел 4) не хватало объектов:
5 в двух окнах рабочих проектов (график горелки: 3 из 10, EasyAccess: 2 из 24) и 1 в окне 1 пустого проекта.

## 4. Объекты

Поток — архив MFC: классы `CPartObject` (виджеты) и `CDrawObject` (фигуры). Первый объект класса несёт определение
(`FF FF`, схема, имя), следующие — тег класса `0x8000 | номер`. Каждый класс и каждый объект занимает следующий номер
в карте архива, поэтому вставка объекта сдвигает ссылки дальше по файлу; `ebpcmtp.py` их пересчитывает.

**Голова виджета:** тег класса (2 Б), тип (1 Б), имя (CString), 12 Б флагов, 3 имени устройств, 20 Б (нули или
идентификатор), 3 байта типа адреса, 3 строки адреса, дальше данные вида: рамка (4 × `u32`), цвета, подписи (текст, шрифт,
размер в пунктах 1 Б, x, y), у картинок — GUID файлов по состояниям.

**Короткая голова** (проверено): тег класса, `u16` номер, необязательные `00 06`, потом `00 04 00`, флаг (`00`/`01`),
`00 00 00`, `00` или `10`, ASCII-строка с `u16` длиной («Local HMI»). Младший байт номера в записи называется «типом», но
это не вид объекта. Содержимое не разобрано. Встречаются:
- номера 0x15d, 0x253, 0x33d (рядом с графиком), 0x847 (EasyAccess), 0x14a (главное окно) — с `00 06`;
- номер 0x148, журнал событий в окне 1 (тексты «Date», «Time», «User name», «Action»…) — без `00 06`. В сборке .300 это
  первый виджет файла и несёт определение класса, в .421 определение стоит в окне 0 (виджет 0x2f), а журнал — ссылка.

## 5. Адреса и устройства (проверено)

- Три имени устройств лежат в порядке «2-й адрес, 1-й, 3-й» (762 виджета из 763). Типы адресов (3 байта) и строки адресов
  идут в порядке слотов 1, 2, 3.
- **Байт типа адреса — это тип данных.** OPC UA: `c1` — BOOL (442 из 444), `c3` — INT (113 из 113), `0b` — UINT (13 из 13),
  `06` — UDINT (4 из 4). Память панели: `08` — LW, `00` — LB, `98` — PLW, `99` — PLW_Bit.
- Устройства в проверенных проектах: «OPC UA Client» и «Local HMI» (пустое имя — у объектов без адресов).
  **Modbus и REAL не встречались:** слова «Modbus» нет ни в одном из трёх проектов (поиск по ASCII и UTF-16). Как они
  записаны, неизвестно, нужен проект с Modbus-устройством и тегом REAL.
- Привязка тега в объекте — строка `имя (ns:2;s:имя)`; тег должен быть в таблице тегов (иначе `cmtp_check` покажет
  `tag_missing`).

## 6. Виды объектов

Опознаны (проверено на подписях и размерах): Text `0x15` (493), Picture `0x16` (155), BitLamp `0x17`, SetBit `0x19`,
ToggleSwitch `0x1b`, NumericInput `0x1d`, NumericDisplay `0x1e`, ASCII `0x20`, FunctionKey `0x21` (862), QRCode `0x50`;
фигуры Rect (326) и Line (70). Простые объекты весят 200–500 Б, кнопки и переключатели около 1 КБ.

Не опознаны или опознаны по виду (количество в рабочем проекте на 88 окон):

| Тип | Шт. | Размер | Где и что по виду |
|---|---|---|---|
| `0x18` | 23 | 5–6 КБ | 20 в главном окне; индикатор из нескольких состояний с картинками |
| `0x1a`, `0x24` | 29, 5 | 0,7–5,7 КБ | окна клавиатур (ASCII), слово и лампа слова |
| `0x1c` | 4 | 5,5–10 КБ | окна EasyAccess: тексты состояний |
| `0x1f` | 6 | 0,7 КБ | ввод ASCII, пароль |
| `0x22` | 1 | 1,9 КБ | экранная заставка |
| `0x28` | 7 | 0,6–1,1 КБ | системное окно 2: подтверждение операции |
| `0x29` | 1 | 7,2 КБ | график |
| `0x2a` | 7 | 0,7–1,1 КБ | окно параметров горелки |
| `0x2f` | 1 | 0,8 КБ | пустой проект: первый виджет файла (окно 0) |
| `0x32` | 1 | 1,9 КБ | журнал аварий |
| `0x40` | 5 | 5–6 КБ | список выбора (например, виды зерна) |
| `0x2b`, `0x30`, `0x48`, `0x4a` | по 1 | 0,2–1,1 КБ | системные окна и общее окно |

## 7. Как проверять разбор

1. Контейнер: `dump(load(файл)) == файл`.
2. Полнота: прочитано == объявлено в каждом окне.
3. Сцена и PNG для каждого окна без ошибок (88 и 90 окон, около 19 с).
4. Статистика по всему проекту (например, пары «устройство — адрес»: 762 против 1).
5. Правки открывает EasyBuilder: человек за ПК или `ebpro-gui` (в песочнице EasyBuilder нет).

## 8. Что нужно, чтобы создавать проект с нуля

- **Пустой проект от самого EasyBuilder** для каждой панели и протокола (Файл → Новый → модель панели → сохранить; ещё с
  устройством OPC UA или Modbus TCP). Есть пустой проект 1024×600 (6.10.02.421), без устройств, кроме «Local HMI».
  Системные настройки и список устройств, судя по хвосту файла, лежат там и не разобраны, поэтому «с нуля» = пустой проект
  панели + всё остальное инструментом.
- **Типизированный разбор объектов:** каждый вид — набор полей с точными смещениями, запись обратно — те же байты.
  Проверка — раздел 7.
- **Фабрика объектов:** создать объект вида X с рамкой, подписями, картинками и адресами (BOOL/INT/UINT/UDINT уже
  известны).
- **Образцы:** проект с Modbus-устройством и тегом REAL; по одному объекту каждого неопознанного вида с известными
  настройками.
- **Разбор самого EasyBuilder:** [REA](https://github.com/mytechnotalent/rea) — реверс-фреймворк на Rust (разбор PE,
  дизассемблер, `rea decompile` в псевдо-C). Цель — `Serialize` класса `CPartObject` и `CDrawObject` в
  `EasyBuilderPro.exe`: из него берутся точные поля каждого вида. Нужны `EasyBuilderPro.exe` и DLL из папки установки
  (6.10.02.421). Установщик на сайте Weintek отдаётся только после входа в аккаунт.

Разбирать формат можно только ради работы с собственными файлами проектов и лицензированной программой.
