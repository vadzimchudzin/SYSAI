## 0. Резюме на одной странице

1. **MCP — не главный виновник.** ФАКТ: все 82 инструмента всех 8 серверов — 16,9k токенов (4–6% среднего запроса в 273k); набор по умолчанию (57 инструментов) — 10,9k. В Hermes ≥ 0.20 (код синхронизатора целится в ≥ 0.22) схемы MCP вообще не отправляются: их заменяет встроенный Tool Search (мост + список ≈ 2,4k). «99,3%» — строка собственного теста проекта *mcptoon* (5 инструментов: 1519 → 11 токенов); она считает только определения. Для вашей системы обёртка вроде Code Mode даст ≤ 2–6% счёта.
2. **Главная причина — история диалога.** 89–94% каждого запроса (≈ 242–257k токенов) — накопленные результаты инструментов, записанные файлы, вложения, картинки. SYSAI не задаёт Hermes ни порог сжатия, ни `context_length`, ни лимиты на ответы инструментов; на странице «Расходы» нет строки «сжатие» (ГИПОТЕЗА: сжатие не срабатывало ни разу). Простая модель с этими допущениями воспроизводит сразу все четыре цифры вашего скриншота: 273k на запрос, 38,8M токенов, кэш 98%, $5,05.
3. **Откуда доллары:** 64% счёта — чтение кэша, то есть «размер контекста × число запросов» (растёт квадратично с длиной сессии). У `gpt-6.1-terra` цена удваивается с 272k токенов в запросе, а ваш средний запрос — 273k. Каждая пауза человека дольше срока жизни кэша добавляет перерасход: пять пауз ≈ +39% (МОДЕЛЬ).
4. **Что экономит больше всего (МОДЕЛЬ на ваших цифрах):** сжатие контекста на 150–200k: −53…−56%; отдельная сессия на каждый этап: −59…−64%; урезание больших ответов инструментов: −32…−48%; убрать *все* определения MCP: −4…−6%.
5. **«3–5 $ за проект»** достижимо только вместе со структурными изменениями: компактная спецификация вместо сотен КБ ST и скриптов от LLM, готовые генераторы, индексы вместо чтения файлов, дешёвые модели на механических этапах. Но «25 $» нужно сверить: страница «Расходы» показывает $5,26 за всю сеть, а метки проекта сейчас не отправляются — стоимость проекта в SYSAI не считается вообще.
6. **Jev:** причину 5 ошибок по скриншоту назвать нельзя (нет карточки «Отказы и сбои»). «5 из 5» вводит в заблуждение: успешные запросы записываются под ответившей моделью, поэтому строка Jev содержит только неисправленные сбои. Сегодня без кода: главная модель → `sysai/mid`. Дальше: патч на 37 строк (готов), проверка здоровья, позже свой маршрутизатор. **Срочно, отдельно от Jev:** модели по умолчанию в шлюзе перестают существовать 01.12.2026, 11.12.2026 и 14.01.2027.
7. **Machine Expert:** сгенерированный проект ни разу не открывали в настоящем ME (проверяли на «поддельном» ME с двумя правилами). На 30 внесённых реалистичных ошибках (набор небольшой и синтетический — ориентир, не статистика) наш `plc_check` блокирует 3 (10%) и молчит про 16 (53%). Главный подозреваемый — привязки каналов, оставшиеся от шаблона и указывающие на удалённые переменные. 30 минут на ПК инженера (протокол «бисект») превращают гипотезы в факты.
8. **Контроллеры:** живого кода нет. Безопасный первый шаг — инструмент `plc-live`, только чтение, по OPC UA. Запись, загрузка, пуск и останов — только человек.
9. **Экраны:** каталога элементов нет, `pic-index` смотрит только на имена файлов. Предлагается индекс из пяти инструментов на SQLite; картинки размечаются по именам, затем по использованию в проектах и только остаток — один раз дешёвой моделью («500 иконок ≈ $0,03–0,08»). Экран на 12 механизмов: ≈ 0,30–0,40M токенов сегодня → ≈ 32–48k с индексом (МОДЕЛЬ).
10. **Беспорядок в папке, «можно создать файл?», диалоги:** причины найдены в нашем коде и решаются в фазе П2.

**Предлагаю начать с П0–П2** (замеры, токен-диета, порядок и удобство): малый риск, самый большой эффект. Параллельно — 30-минутная проверка Machine Expert на ПК инженера.

### 1.2 Jev

- ФАКТ: `typesafe/jev-router` — реальный публичный роутер OpenRouter (создан 25.09.2026, контекст 1 000 000, цена `-1`, поддерживает tools/streaming/reasoning). Наш запрос соответствует документированному контракту: плагин `jev-router` с `cost_tier`, `models`, `excluded_models` (у нас 122–150 slug при лимите 1024); `reasoning.max_tokens` мы вырезаем, как требует документация.
- ФАКТ (проверено запуском настоящего `gateway.py` против фальшивого апстрима): сбой Jev с кодом 400/404/500/502/503/504 уходит на уровень «mid» и записывается как **успешная** строка под ответившей моделью (`route = jev→mid: HTTP …`). Строка `typesafe/jev-router` с ошибкой возможна только для неисправленных классов: 401/402/403/408/413/422/429/529, таймауты, «200 + тело с ошибкой», ошибка внутри потока. Значит, «5 из 5» — свойство строки Jev, а не доказательство, что падает каждый запрос `sysai/auto`.
- Пустая модель («—», 6 ошибок): так записываются только отказы `prepare()` — лимит бюджета, запрещённый уровень, нет ключа, нет модели/сообщений. Вероятнее всего `budget_exceeded`: лимит компании по умолчанию $5,00 в сутки, лимит профиля инженера $3 в сутки, а сумма на экране $5,26 (ГИПОТЕЗА). Hermes повторяет отказ 3 раза, поэтому 6 строк ≈ 2 заблокированных хода.
- ФАКТ: `sysai/auto` — главная модель по умолчанию только у профилей, созданных с 04.11.2026; существующие профили не мигрируют. Возможно, 5 строк Jev — короткий эксперимент (ГИПОТЕЗА).
- Предохранитель `JEV_REST` (600 с) работает «как написано», но открывается только на 404/503, живёт в памяти процесса и не виден в интерфейсе.
- Решающая проверка — два клика: карточка «Отказы и сбои» на странице «Расходы» и фильтр ошибок на странице «Трасса» (см. П0.1). Из-за ограничения решающей модели Jev (262 144 токена в промпте при среднем запросе 273k) длинные диалоги — ещё одна возможная причина (НЕ ПРОВЕРЕНО).

### 1.3 Machine Expert: что известно и почему «не компилирует»

**Что уже сделано и надёжно (ФАКТ, из передачи от 12.11.2026):** контейнер `.project` читается и пишется без Machine Expert — «закрытый» вид оказался режимом проверки целостности, ключ считается из заголовка файла; три проекта заказчика читаются и записываются байт в байт; программа из `.project` совпадает с `.export` (49 POU, 11 списков, задачи); новый проект собирается из папки ST и шаблона; ядро CODESYS 3.5.19.40 под Wine открывает собранные файлы.

**Чего не проверено (ФАКТ):** открытие в окне Machine Expert и компиляция никогда не выполнялись на нашем результате. Цикл компиляции проверен только на `fake_machine_expert.py`, у которого «компилятор» знает два правила. Текста ваших ошибок компиляции у нас нет, поэтому ниже — ранжированные гипотезы.

**Сильные стороны и дыры проверки (замер: 30 внесённых ошибок, которые компилятор отвергнет):**

| Слой | Результат |
|---|---|
| `plc_check` (сейчас — эвристический lint) | блокирует 3 из 30 (10%), предупреждает 11, молчит 16 (53%): все ошибки типов, опечатки в членах, параметры вызова FB, `&&`/`!=`, незакрытый комментарий, неверный литерал времени, зарезервированное слово, рекурсия, задача → FB |
| `plc_project_build` | пишет `.project`, даже если есть только предупреждения; отчёт «сходится» не проверяет привязки |
| реальный парсер `blark` (GPL-2.0) с адаптером | отвергает 12 из 12 синтаксических ошибок |
| `iec-checker` v0.4 (LGPL-3.0) | ≈ 10–12 из 12 |
| lint + blark + iec-checker вместе | 18–19 из 30; оставшиеся 11–12 — семантические (типы, члены, параметры вызова, рекурсия, вид задачи) |

**Топ причин (ГИПОТЕЗЫ, по убыванию «сколько содержимого не проверено»):**
1. **R4 — привязки каналов.** Проект из шаблона сохраняет привязки «канал → переменная» после удаления программы: каналы указывают на несуществующие переменные (`Application.old_0`). Наш же тест это подтверждает (`tests/test_hub_seed_plc_project.py:265-277`), а отчёт сборки всё равно пишет «сходится». Проверяется без Machine Expert, за часы.
2. **R1 — синтаксис ST**, написанный LLM (≈ 61 КБ на скриншоте папки).
3. **R2 — семантика ST:** необъявленные имена, типы, параметры вызовов, преобразования `X_TO_Y` (43 из 81 частых имён lint помечает как «необъявленные»).
4. **R3 — ссылки на библиотеки:** FB из `Util` и системных библиотек M241 может не быть в менеджере библиотек шаблона.
5. **R7 — задачи:** новая задача собирается вручную; если в `project.json` нет ключа `tasks`, задачи шаблона очищаются и ничего не запускается.
6. **R8–R11 — кэши и версии:** удалённые `*.precompileinfo`, неизменённые `profile*`/`redundantproject*`/`devicesmetainformation`, идентичность контроллера (устройство `101a 0710`, описание 5.2.11.24) не читается и не сверяется с установленным ME. Это определяет, откроется ли даже тривиальная программа; без запуска не узнать.
- Около 70% поверхности риска проверяется офлайн (R1, R2 для типов проекта, R4, R5, R6, R7, R12, R13 полностью; R3, R9–R11 — частично, с данными с ПК).

**Компиляция на ПК инженера** существует только как неиспытанный дизайн (`hub/seed/machine-expert`). ФАКТ: из ≈ 80 имён скриптового API в `me_job.py` все, кроме 6 (охраняемые запасные варианты), есть в публичной документации CODESYS ScriptEngine. НЕ ПРОВЕРЕНО: принимают ли `LogicBuilder.exe`/`LogicBuilderShell.exe` ключи `--runscript/--noUI` — публично не документировано; автор публичного набора CODESYS-MCP пишет, что тот «никогда не запускался» на Machine Expert. Нужен протокол «бисект» (П0.3).

**Контроллеры.** Живого соединения в репозитории нет (ни `pymodbus`, ни `asyncua`; `me_scan`/`me_online` работают только через ME и не запускались). ФАКТ (руководство Schneider EIO0000003059.11): на M241 OPC UA (порт 4840) и Modbus TCP (502) по умолчанию выключены; политика OPC UA по умолчанию Basic256Sha256 + SignAndEncrypt, 2 сессии, символы только для чтения, анонимный вход разрешён, пока не отключён; первый сертификат клиента попадает в карантин, пока человек не подтвердит его в Machine Expert. Machine Expert использует TCP 1105/11740 и UDP 1740. Открытого рабочего клиента онлайн-протокола CODESYS нет. ### 1.4 Экраны EasyBuilder: каталог, картинки, индексы

- **Каталога элементов нет (ФАКТ).** Агент узнаёт, какие объекты бывают, какие у них состояния и какие картинки подходят, только выгрузкой окна-донора (`cmtp_objects`, `cmtp_scene`) и сопоставлением имён файлов (`pic-index`). Фабрики объектов нет: создание — клон или импорт из донора той же ревизии. Типов объектов с кодами 17, из них 6 — догадки (`ebpcmtp.py:499`).
- **`pic-index` читает только имена** (файлы, папки, словарь из 27 видов оборудования, слова состояний, ручные метки по sha1). Он не смотрит на пиксели и не видит картинки внутри `.cmtp`: у них нет имён, `cmtp_extract_images` называет их смещением и пропускает BMP; имена групп картинок EasyBuilder разбираются, но агенту не показываются.
- **Токены уходят на ответы, а не на определения:** определения `ebpro-cmtp` + `pic-index` — 5,9k на запрос (2,2%); один полный `cmtp_objects` — 143 токена на объект (окно из 30 объектов — 4,3k); `cmtp_tags` без фильтра на 588 тегов — 19,5k; `pics_list` на 733 картинки — 17,9k; компактный построчный формат того же окна в 4,8 раза меньше. Модель экранного этапа для 12 механизмов: сегодня 0,30–0,40M токенов и 138–150 обращений; с индексом ≈ 32–48k и 63–87 обращений (МОДЕЛЬ).

Прагматичный путь — «набор семян»: мини-проекты, сохранённые самим EasyBuilder (по одному на вид элемента, панель, протокол), как индексируемые шаблоны.

### 1.5 Беспорядок в папке, «можно создать файл?», диалоги

- **Папка (три причины, все в нашем коде):** (а) навык `plc-project` велит писать всё в `plc/` (`SKILL.md:28,67`); (б) окно показывает файлы `plc/ hmi/ docs/` плоским списком под «Сделано агентом» (`renderer/js/projects.js:158-166`); (в) генераторов, которые планирует `TASKS.md` (ОПО-10.1/10.2/9.4), нет, поэтому LLM пишет собственные скрипты каждый раз (на скриншоте ≈ 46 КБ скриптов, ≈ 22 КБ заметок, ≈ 29 КБ csv/json рядом с ≈ 61 КБ ST). Скриншот — это «Файлы компьютера» (Проводник), а не вкладка «Проекты».
- **Вопрос «можно создать файл?» — это согласование правок самого Hermes** (`edit_approval_policy`, для каждой новой сессии ACP жёстко `ask`), а не правило SYSAI. SYSAI выставляет `approvals.mode: off`, но это относится только к командам оболочки. Карточка даёт «Разрешить один раз» и «Отклонить»; число вопросов равно числу вызовов `write_file`/`patch`. Команды оболочки уже идут без вопросов, поэтому автоодобрение правок почти не снижает безопасность — но нужны границы (папка проекта, `materials/`, секреты, удаления) и откат.
- **В окне уже есть переключатель** этой политики (`composer.js:14-21`), но на вашем скриншоте его нет — причину по коду не определить (проверка: П0.1, V6).
- **Диалоги Hermes хранит** (`<профиль>\state.db`), окно умеет `session/list` и `session/load`. Теряется выбор диалога (всегда создаётся новый черновик, `app.js:260-266`), черновик сообщения и связь с проектом; сессии создаются с `cwd` = домашняя папка (`main.js:419`). Почему вы видите «не сохраняются», по коду определить нельзя (три гипотезы и одна проверка в отчёте E).
- **Браузер:** в Hermes уже есть `web_search`/`web_extract` (лимит ответа 15 000 символов) и `browser_exec`; хук SYSAI разрешает их при `internet.mode == all`. Работают ли они на ПК инженеров — НЕ ПРОВЕРЕНО. Playwright MCP в собственной документации рекомендует CLI + навыки ради токенов.

### 2.2 Принципы

1. **LLM пишет только то, что нельзя вывести кодом** — спецификацию и редкую нестандартную логику. Рутину делают проверенные генераторы с эталонными тестами.
2. **Индекс отвечает «что можно поставить и как», и возвращает готовый рецепт** (список операций), а не заставляет модель читать дампы.
3. **Любой ответ инструмента маленький и постраничный**, большое уходит в файл `_work/…` с путём и счётчиками.
4. **Любой этап заканчивается проверяемым отчётом**; «готово» ставится только по свежему отчёту без ошибок, а не по тексту агента.
5. **Один этап — одна сессия**, состояние в `project.md`/`pipeline.json`/отчётах, а не в памяти диалога.
6. **Целевой-нейтральный слой** (роли, состояния, сигналы) + адаптеры под конкретное ПО: сейчас Machine Expert (ST) и EasyBuilder; Haiwell HappyPLC (LD) и ONI — позже без переделки.

## 3. Бюджет токенов и стоимости

**Как считаются деньги.** Стоимость ≈ Σ по запросам (размер контекста × цена чтения кэша) + новые токены × цена входа + выход × цена выхода. Размер контекста растёт с длиной сессии, поэтому стоимость растёт примерно квадратично: главные рычаги — короче сессия (по этапам), меньше рост за запрос (ответы, файлы), меньше запросов (генераторы, индексы), дешевле модель на механике.

**Сначала измеряем.** «25 $» не воспроизводится: страница «Расходы» показывает $5,26 за всю сеть, а проект в SYSAI не считается (заголовки не отправляются). Нужна база «до» в долларах на проект — это П0.5 и П1.5. Без неё обещание «3–5 $» бессмысленно.

**Ориентиры по этапам** (ГИПОТЕЗА, калибруем после П1; это не обещание):

| Этап | Что делает LLM | Модель | Ориентир, $ за проект |
|---|---|---|---|
| Приём материалов → спецификация | читает карточки листов, задаёт вопросы инженеру | mid, strong на спорном | 0,6–1,0 |
| PLC: генераторы + нестандартная логика | пишет только нестандартные куски | mid / strong | 0,4–0,8 |
| Проверки и компиляция (цикл ≤ N) | чинит по структурным отчётам | mid | 0,3–0,7 |
| Экраны: индекс + рецепты | выбирает элементы и картинки по подсказкам индекса | cheap / mid | 0,4–0,8 |
| Документация | сводит в docx | cheap / mid | 0,2–0,4 |
| Резерв и обзор | по необходимости | strong | 0,3–0,6 |
| **Итого** | | | **2,2–4,3** |

**Относительные цели:** П1 — не менее −50% к базе на том же тестовом проекте; П3–П5 — ещё в 2–4 раза за счёт генераторов и индексов (оценка по моделям экранного этапа и ST). Если база окажется $5 за проект, цель в абсолюте будет ниже $2; если $25 — упрёмся в $4–6. Цель «в идеале 3–5 $» остаётся ориентиром, который мы подтвердим или скорректируем измерениями.

**Ступени:** 0 — офлайн, ожидаемая карта тегов; проверка в симуляции ME (`me_online simulation`, не запускалось). 1 — пассивное: TCP-подключение к 4840/502/11740, `me_scan`. 2 — **OPC UA только чтение**: права пользователей включены, анонимный вход отключён, отдельный пользователь в группе «Function OPC UA», Basic256Sha256 + SignAndEncrypt, сертификат подтверждён человеком в Security Screen, символы только для чтения, сессий ≥ 2 (панель занимает одну), подписка ≥ 1 с. Дополнение: Modbus FC 3 по читаемому окну `%MW60200–61999` (unit 255) в изолированной сети. 3 — любые переменные «как в Machine Expert»: `login(Keep)` + `read_value` через `me_online` (тяжело, нужна лицензия, не проверено). 4 — запись только в симуляции и по `confirm:true`. 5 — загрузка, пуск, останов, прошивка — **только человек**.

**Следствие для генераторов:** публиковать в GVL плоский блок «наблюдаемости» (состояния, слова аварий), потому что внутренности FB через OPC UA/Modbus не видны; включать сервер OPC UA и публикацию символов «только чтение» в генерируемом проекте. Прошивка M241 не ниже 5.4.13.12 (CVE-2025-13901); не направлять реверс-инженерные клиенты (HAHermsen, CoDe16) на боевые контроллеры.

**Приёмка П6:** на стенде или симуляторе `plc_read` возвращает значения всех опубликованных тегов проекта; записи нет в коде; доступ к сетям ПЛК — только из списка правил.

### П7. Маршрутизатор и устойчивость (около недели, после двух недель данных)

1. **Собственный детерминированный маршрутизатор** вместо `sysai/auto`/Jev как движок по умолчанию: уровень выбирается по роли, этапу, размеру контекста, наличию картинок; решение **закрепляется на сессию/этап** (смена модели ломает кэш); каждое решение объясняется в `route`. Сначала **теневой режим**: считаем решение для каждого запроса, пишем в `route` как `policy?:cheap`, но не применяем; затем A/B одного и того же этапа на дешёвой и сильной моделях с метриками качества (процент компиляции, число циклов, принятие человеком). Стартовые правила (ГИПОТЕЗЫ): первый ход сессии — strong; циклы чтения/извлечения/конвертации — cheap; циклы «написал код → компиляция» — mid; два подряд сбоя или проверка — strong; ход с картинкой — только на модель с vision.
2. Jev остаётся опциональным движком (`auto_engine: policy|jev`); сравнить с `nvidia/switchyard` (документированный fail-open, закрепление уровня на беседу) — качество на ST/EasyBuilder не измерено.
3. **Канареечный канал для окна**: сейчас пуш в `agents/desktop/**` уходит всем инженерам автоматически (авто-обновление включено, канарейки нет). Предложение — серверная настройка `desktop_pin_sha` и исключение для вашего агента.
4. Бюджет проекта и дневные лимиты начинают работать (после П1.5); монитор жизненного цикла моделей.
5. Расписание тяжёлых необязательных заданий вне пиковых окон DeepSeek.
