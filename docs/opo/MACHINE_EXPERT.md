# Machine Expert: как устроен файл проекта и как агент создаёт проекты

Записано 12 ноября 2026 (заменяет запись от 10 ноября: тогда файл `.project` считался закрытым). Формат взят из
самой программы — папки EcoStruxure Machine Expert 2.2 (ядро CODESYS 3.5.19.40) — и проверен на трёх проектах ОПО.
Инструменты: `hub/seed/plc-kit` (читает и пишет `.project`), `hub/seed/machine-expert` (компиляция и контроллер на
ПК с программой).

## 1. Итог

- Файл `.project` **читается и пишется без Machine Expert**. «Закрытый» вид — не шифрование паролем, а «проверка
  целостности проекта»: всё нужное для открытия лежит в заголовке самого файла.
- Три проекта («Родина», «Достоево», «Вульковский рассвет») читаются целиком и записываются обратно **байт в байт**.
  Программа из `.project` совпадает с их `.export` без отличий: 49 POU, 11 списков переменных, задачи.
- Новый проект собирается из папки ST и **шаблона** — `.project` с тем же контроллером и модулями
  (`plc_project_build`). Собранные проекты открывает и пересохраняет ядро CODESYS из Machine Expert 2.2.
- **Не проверено:** открытие в окне Machine Expert и компиляция (раздел 7). Нужен один запуск на ПК с программой.

## 2. Что разбирали и чем

| Что | Откуда | Зачем |
|---|---|---|
| Папка программы Machine Expert 2.2 (`LogicBuilder`, 486 МБ) | диск заказчика, `V2.2.rar` | библиотеки ядра и объектов |
| `ObjectManager.plugin.dll`, `SecurityManager.plugin.dll` 3.5.19.40 | там же | контейнер файла, загрузка и сохранение |
| `BinaryArchive.plugin.dll` | там же | двоичный формат объектов и таблиц |
| `TextDocument`, `POUObject`, `GVLObject`, `DUTObject`, `TaskObject`, `DeviceObject`… | там же | поля объектов |
| `Rodina.project`, `Dostoevo.project`, `Vulkovski.project` и их `.export` | диск заказчика | проверка чтения и записи |

Библиотеки — .NET, разбираются декомпилятором: `ilspycmd -p -o src Имя.plugin.dll`. Клиентских проектов и файлов
программы в репозитории нет.

## 3. Контейнер

Программа читает первые 16 байт файла и по ним выбирает способ загрузки (`Project.Load`):

| Метка (GUID) | Режим | Секрет |
|---|---|---|
| `{00A80513-758B-4e0b-9EDE-5AA029530F3A}` | пароль | вводит человек |
| `{A18D0139-2E39-4019-9AF6-5202425B6D87}` | аппаратный ключ | на ключе |
| `{101AA415-9A03-4F2D-8A39-5E1303921998}` | сертификат X.509 | закрытый ключ сертификата |
| `{33ED8923-BD14-4B93-8DA9-5D9108C53235}` | **проверка целостности** | в самом файле |
| другое | без защиты | файл — сразу ZIP |

Проверка целостности (так сохраняет Machine Expert 2.2 по умолчанию; все три проекта ОПО такие):

```
16 байт   метка 23 89 ED 33 14 BD 93 4B 8D A9 5D 91 08 C5 32 35
16 байт   начальный вектор (IV)
16 байт   соль
32 байта  SHA-256 открытого ZIP
остаток   AES-256-CBC, дополнение PKCS7: ZIP проекта
```

Ключ = `PasswordDeriveBytes(SHA-256 из заголовка, соль, "SHA256", 1000).GetBytes(32)` — это SHA-256 от «хеш + соль»
и ещё 999 раз SHA-256 от результата. При загрузке программа сверяет SHA-256 расшифрованного ZIP с заголовком и при
отличии отказывается открывать (`ProjectIntegrityException`). Файл без метки (обычный ZIP) она открывает тоже.

Проекты с паролем, ключом или сертификатом инструмент не читает.

## 4. ZIP и записи

Machine Expert пишет ZIP без сжатия, но методом 8 (deflate из «несжатых» блоков по 32763 байта); у всех записей одно
время — время сохранения. `plc-kit` пишет так же: три проекта воспроизводятся байт в байт. Читает программа любой
обычный ZIP.

| Запись | Что это |
|---|---|
| `<guid>.meta` | объект дерева: GUID, родитель, имя, свойства, тип, встроенные типы, время (.NET ticks) |
| `<guid>.object` | содержимое объекта |
| `__shared_data_storage_string_table__.auxiliary` | таблица строк: каждая строка проекта — один раз |
| `__shared_data_storage_schema_table__.auxiliary` | таблица схем: тип + поля (имя, формат, тип построения) |
| `<guid>_decl_lineids.auxiliary`, `<guid>_impl_lineids.auxiliary` | JSON: где кончается каждая строка текста, её постоянный номер, SHA-256 текста |
| `*.precompileinfo.auxiliary` | кэш прекомпиляции (свои таблицы внутри) |
| `profile.auxiliary`, `profile7.auxiliary` | профиль: версии компонентов (старый двоичный формат) |
| `deviceobjectparameters_<guid>.auxiliary`, `deviceobjectdatatypes_<guid>.auxiliary` | параметры устройств (старый формат в deflate) |
| `redundantproject*.auxiliary`, `devicesmetainformation.auxiliary`, `engineering*.auxiliary` | XML и текст Schneider: сведения о проекте, устройствах, версиях |

`.meta` загружается, только если есть парный `.object`.

## 5. Двоичный формат объектов

Числа — little-endian; `mbui` — целое по 7 бит на байт, младшая группа первой, бит 0x80 — «есть продолжение».

**Запись `.meta` / `.object`:** `u32 0x28092002`, `u32 0`, `u32 0`, `u32 0`, `u32 длина`, затем одно значение с
меткой формата. Хешей и контрольных сумм внутри нет.

**Таблица строк:** `mbui число`, затем `mbui номер, mbui длина, UTF-8`. Новая строка получает номер «наибольший + 1».
Текст программы — одна строка на объявление и одна на код, переводы строк `\n`.

**Таблица схем:** схема — это вид одного сохранённого экземпляра: GUID типа и список полей `(имя, формат, тип
построения)`; формат — тот, что был у значения (пустое поле — формат Null). Поэтому у одного типа несколько схем.
Номера схем идут подряд с 1.

**Значения:**

| Метка | Формат |
|---|---|
| 0 | Null |
| 1…13 | Bool, Byte, Sbyte, Char, Decimal, Double, Float, Int, Uint, Long, Ulong, Short, Ushort |
| 14 | String — `mbui` номер в таблице строк |
| 15 | объект — `mbui` номер схемы, затем значения полей в порядке схемы, без меток |
| 0x80 | TypeConverter — строка + имя типа (`System.Guid`, перечисления, время) |
| 0x81…0x84 | массив и список: однородные (общая метка элемента) и разнородные |
| 0x85…0x88 | словари: однородные и разнородные ключи и значения |
| 0x40…0x45 | списки и словари, которые создаёт сам объект-владелец |

**Объекты программы** (GUID типов одинаковы в CODESYS и Machine Expert):

| Объект | Тип | Поля |
|---|---|---|
| программа, блок, функция | `6f9dac99-8de1-4efc-8465-68ac443b7d08` | `SpecialFunc`, `Implementation`, `Interface`, `UniqueIdGenerator`, `POULevel`, `ChildObjectGuids`, `AddAttributeSubsequent` |
| метод | `f8a58466-d7f6-439f-bbb8-d4600e41d099` | `Implementation`, `Interface` |
| действие | `8ac092e5-3128-4e26-9e7e-11016c6684f2` | `Implementation`, `UniqueIdGenerator` |
| список переменных | `ffbfa93a-b94d-45fc-a329-229860183b1d` | `Interface`, `NetVarProperties`, `ParameterList`, `AddAttributeSubsequent` |
| тип данных | `2db5746d-d284-4425-9f7f-2663a34b0ebc` | `Interface`, `UniqueIdGenerator` |
| папка | `738bea1e-99bb-4f04-90bb-a7a567e74e3a` | `StructuredViewGuid` |
| задача | `98a2708a-9b18-4f31-82ed-a1465b24fa2d` | `Kindoftask`, `Priority`, `Interval {Time, Unit}`, `Watchdog`, `PouList [{Name, Comment}]`, … |
| приложение, конфигурация задач, устройство | `639b491f-…`, `ae1de277-…`, `225bfe47-…` | из шаблона, не создаются |

- `Interface` (`a9ed5b7e-…`) и `Implementation` на ST (`3b83b776-…`) держат `TextDocument` (`f3878285-…`):
  `TextBlobForSerialisation` — текст, `LineInfoPersistence` — имя записи с номерами строк.
- Графическая реализация: LD / FBD — `25e509de-33d4-4447-93f8-c9e4ea381c8b` (сети, элементы, операнды), CFC —
  `32d3375e-c010-41e2-9e43-b2fbf4f2b374`. Читаются имена элементов; создавать их инструмент не умеет.
- Что блок, а что программа — говорит текст объявления (`PROGRAM`, `FUNCTION_BLOCK`, `FUNCTION`). Методы и действия
  — дочерние объекты (родитель в `.meta`); `ChildObjectGuids` у POU пуст.
- Папка — вид, а не родитель: объект лежит в «Application», а папку называет свойство `829a18f2-…` его `.meta`.
- Канал устройства: `IoMapping → Mappings → [{Variable}]`; `Application.x0_0` — переменная программы,
  `{CreateVariable: true, Variable: "idwDI_IDW0"}` — переменную объявляет привязка.
- OPC UA (объект Schneider `54fe9644-1b3c-4386-ae33-e37a105a31f4`): `SelectedVariables` — список `Список.Имя`,
  `SelectedVariablesWithAccessRights` — права (8 — по умолчанию).

Полный разбор — в коде: `hub/seed/plc-kit/mearchive.py` (контейнер, ZIP, таблицы, архивы), `meproject.py` (объекты).

## 6. Как собирается новый проект

```
папка ST (пишет агент, проверяет plc_check)   +   шаблон .project (контроллер, модули, библиотеки)
        │  plc-kit: plc_project_build
        ▼
Line.project  ── читается обратно и сверяется с папкой
        │  Machine Expert: открыть, скомпилировать (machine-expert: me_build)
        ▼
ошибки компилятора с файлом .st и строкой ──► агент правит .st ──► plc_project_build (обновление) ──► …
```

**Почему шаблон.** Объект устройства хранит разобранное описание из репозитория устройств Machine Expert (параметры,
каналы, соединения) — сотни килобайт на контроллер. Репозиторий ставится вместе с программой (`C:\ProgramData`), в
присланной папке его нет. Поэтому устройства берутся готовыми: из проекта с тем же контроллером и модулями. Все три
проекта ОПО — TM241 (идентификатор `101a 0710`, версия описания 5.2.11.24) с модулями TM3.

**Что делает `plc_project_build`:** вынимает программу шаблона (программы, блоки, списки, типы, папки), создаёт
объекты из папки ST в «Application», настраивает задачи по `project.json`, при связи OPC UA записывает список
публикуемых переменных, убирает устаревшие кэши прекомпиляции, сохраняет с проверкой целостности. Переменные на
каналах — `plc_io`, `plc_io_map`.

Создание проекта скриптом внутри Machine Expert (`machine-expert`: `me_create`) остаётся запасным путём: по модели
контроллера без шаблона, на ПК с программой.

## 7. Что проверено и что нет

| Что | Состояние |
|---|---|
| Контейнер: открыть и собрать обратно тот же файл | три проекта ОПО — байт в байт; свой AES на Python даёт тот же файл |
| ZIP, таблицы строк и схем, все `.meta` и `.object` | три проекта — байт в байт (296 объектных записей) |
| Программа из `.project` против `.export` тех же проектов | совпадает: 49 POU, 11 списков, задачи |
| Объекты, созданные инструментом, против созданных ядром CODESYS | совпадают поле в поле (программа, блок, функция, метод, действие, список, 4 вида типов, папка) |
| Новый проект на шаблоне «Достоево», «Родина», «Вульковский рассвет» | ядро CODESYS 3.5.19.40 открывает: все объекты прочитаны, ни одного неизвестного; пересохраняет без изменений в объектах |
| Тот же проект через полный путь открытия ядра (`projects.open`) | те же сообщения, что у исходного проекта (только «библиотека не установлена» — их нет на стенде) |
| Круг «`.project` → папка ST → новый `.project`» на «Достоево» | текст 12 программ на ST и 2 списков тот же (с точностью до пустых строк по краям) |
| **Открытие в окне Machine Expert 2.2** | **не проверено**: оболочке нужна лицензия Schneider |
| **Компиляция, загрузка в контроллер** | **не проверено**: нужны библиотеки и репозиторий устройств |
| Проверки Schneider при открытии (совместимость контроллера, версия проекта) | не выполнялись: модули Schneider без оболочки не загружаются |
| Свойства блоков, интерфейсы, графические POU | читаются; не создаются |
| Добавление и удаление модулей | не делается: набор модулей — из шаблона |

**Стенд ядра** (`scripts/me_engine_wine.sh`): папка программы под Wine с .NET 4.8 и маленькая программа-хозяин,
которая поднимает настоящие компоненты CODESYS — менеджер объектов, двоичный архив, объектные модули, скриптовый
движок — без оболочки Schneider. Открывает `.project`, печатает дерево и тексты, пересохраняет, выполняет скрипты
(`projects.create`, `create_pou`…). Повреждённый объект, запись или файл он называет ошибкой.

## 8. Первый запуск на ПК с Machine Expert — что проверить

1. Собрать проект: `plc_project_build` на шаблоне — готовом проекте с тем же контроллером.
2. Открыть файл в Machine Expert 2.2. Записать: открылся ли без сообщений; если есть сообщения — их текст.
3. «Сборка → Компилировать». Ошибки по программе — обычный круг исправлений; ошибки по устройствам, библиотекам или
   «проект повреждён» — записать сюда дословно.
4. Открыть «Конфигурацию задач», привязку входов-выходов модуля и «OPC UA Symbol Configuration»: значения те, что
   записал инструмент.
5. Сохранить проект в Machine Expert и прислать файл: по нему сверяется, что программа меняет при первом
   сохранении.
6. `machine-expert` на этом ПК: `me_find`, затем `me_build` на собранном файле — скрипт внутри программы тоже ещё
   не запускался на живом Machine Expert (`hub/seed/machine-expert/TOOL.md`).

## 9. Связь панели и контроллера

Решается до программы (`plc_link`, plc-kit) по моделям из ТЗ:

| Контроллер | Панель | Связь | Что это значит для программы |
|---|---|---|---|
| с сервером OPC UA (TM241CE…, TM251, TM262) | с клиентом OPC UA (Weintek cMT) | **OPC UA** | переменные по именам; публикуемые перечислены в «OPC UA Symbol Configuration»; адреса не нужны |
| с Ethernet | без OPC UA (Weintek iE / iP / XE / eMT) | **Modbus TCP** | каждой переменной панели — адрес `%M`; панель ведущая |
| без Ethernet (TM241C…) или панель без Ethernet | — | **Modbus RTU** | адреса `%M`; Modbus Manager на Serial Line |

Рядом с `.project` Machine Expert кладёт `<имя>.project.OpcUASymbolConf.map` (опубликованные переменные с местом в
памяти) и `<имя>.project.settings.conf` (настройки сервера OPC UA) — они появляются после компиляции.
