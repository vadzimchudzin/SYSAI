# ОПО: агент в обвязке — подробные задачи

Ветка `sysai-agents_OPO` от актуального SYSAI (`experimental`). **Версия 2:** агент ОПО — обвязка Hermes Agent с
нашими MCP-серверами и навыками из общего SYSAI_Hub. Первая версия плана (модуль внутри SYSAI) заменена этой.

## 0. Цель и как мерим

**Цель.** Проект ПЛК (Schneider, ST и LD), на который сейчас уходит 1–2 месяца, делается за 2–4 дня вместе с правками
и подгонкой. Рутину делает агент, люди проверяют и правят. Порядок: сначала теги и полный проект ST/LD по стилю
компании, потом экраны.

**Как выглядит проект за 2–4 дня:**
- **День 1.** ТО кладёт пакет чертежей → агент инженера сам замечает его, разбирает: все входы-выходы и переменные,
  оборудование, вопросы. Инженер проверяет таблицу тегов, вопросы уходят в ТО.
- **День 2.** Агент генерирует полный проект (ST + LD по стилю компании) и сам собирает его в Machine Expert на ПК
  инженера. Инженер смотрит отчёт сборки и лист «проверить руками».
- **Дни 3–4.** Правки словами → агент поправил → пересборка; подгонка; выдача. Экраны — этап 17.

**Метрики** (считаются автоматически на эталонных проектах, ОПО-7.11):

| Что | Цель |
|---|---|
| Найдено каналов ввода-вывода из чертежей | ≥ 99 % |
| Лишних или ошибочных тегов | ≤ 2 % |
| У тега есть источник (файл, лист, место на листе) | 100 % |
| Неуверенное помечено, а не угадано молча | 100 % |
| Проект собирается в Machine Expert с первого раза | ≥ 95 % |
| Проверки стиля компании проходят | 100 % |
| Время инженера на проект среднего размера | 2–4 рабочих дня |
| Расход на нейронки по проекту | в пределах бюджета, отчёт по факту |

## 1. Как устроено

У каждого инженера **свой агент**: Hermes Agent на его Windows-ПК (рядом с Machine Expert), отдельный профиль
`opo-<логин>`. Свой контекст и память, помнит своего человека, работает с ПК. Умения агента — в MCP-серверах
(инструменты) и навыках (как делать по-нашему).

```
SYSAI (сервер)
├─ вход и уровни доступа людей · агенты и их доступы (настройки)
├─ SYSAI_Hub — один хаб навыков на всю сеть агентов
├─ MCP «sysai»: проекты, база ТО с чертежами, теги, вопросы в ТО, стиль, типовые, журнал
├─ шлюз моделей: модель под задачу, бюджеты, учёт расходов
└─ лёгкий интерфейс: проверка тегов, агенты, доступы, хаб
        ▲ HTTPS, токен агента
ПК инженера (Windows, Machine Expert)
└─ Hermes, профиль opo-<логин>: своя память · навыки SYSAI_Hub (только чтение) + свои
   ├─ MCP: plc-kit (разбор, теги, генерация, проверки) · machine-expert · cad · sysai
   └─ синхронизатор: доступы, навыки, предложения навыков, пульс
```

**Главные решения:**
1. **Доступы — только в настройках SYSAI, никаких подтверждений в Telegram.** В «Агенты → Доступы» задаётся, что
   агенту можно: команды, папки, программы, MCP-инструменты, данные SYSAI, интернет, нейронки, бюджеты, расписание.
   SYSAI превращает это в настройки агента, синхронизатор на ПК применяет их сам. MCP-серверы дополнительно
   проверяют доступы у себя — это не зависит от обвязки.
2. **SYSAI_Hub — один общий хаб навыков для всех агентов сети.** ОПО — первый отдел, потом остальные. Опубликованные
   навыки сами приходят всем агентам, кому разрешены. То, чему агент научился сам, приходит в хаб предложением и
   после утверждения владельцем навыка становится общим. Формат — открытый SKILL.md: подходит Hermes, OpenClaw,
   Claude Code, Codex.
3. **SYSAI — шлюз моделей.** Агенты ходят к нейронкам только через SYSAI: модель под уровень задачи, бюджеты, учёт,
   запасные модели. Ключи нейронок на ПК не попадают.
4. **Вход через SYSAI.** Агент работает от имени своего человека и никогда не получает больше прав, чем у него.
5. **Тяжёлое — на ПК.** Разбор, генерация и сборка идут на ПК инженера; сервер SYSAI (512 МБ) держит данные, хаб,
   шлюз и интерфейс.

**Совместимость с SYSAI (чтобы потом просто влить):**
1. Общее для сети — `app/net/` (агенты, доступы, хаб, MCP, шлюз), таблицы `net_*`; ОПО — `app/opo/`, таблицы
   `opo_*`; то, что ставится на ПК, — `agents/` (plc-kit, machine-expert, cad, синхронизатор, установщик); первые
   навыки — `hub/seed/`; тесты — `tests/test_net_*.py`, `tests/test_opo_*.py`; документы — `docs/opo/`.
2. Существующие таблицы SYSAI не меняются.
3. Включается настройками `agents_on` и `opo_on` (по умолчанию выключено): выключенное — SYSAI работает как раньше.
4. Веб-часть — только лёгкие зависимости на чистом Python.
5. Ветка регулярно подтягивает `experimental`; все тесты SYSAI зелёные.

  уровня — ревизия доступов меняется, ПК применяет сам. Сколько пришло из кэша — в трассе и расходах.

**ОПО-5.6 · Отчёт расходов** · S · ИИ · ✅ готово
- «Сеть агентов → Расходы» (`/agents/spend`): сегодня, 7, 30 или 90 дней, все агенты или один; итог, запросов и
  ошибок, токенов и доля кэша, в среднем за запрос; по дням; по агентам (с дневным бюджетом), проектам, навыкам,
  уровням, моделям, что ответили, и тем, кто спрашивал (главная модель, исполнители, сжатие, зрение); отказы и сбои
  с причиной. CSV для Excel (`/agents/spend.csv`, `;`, UTF-8 с BOM).
- Суперпользователь видит всех, сотрудник — только своих агентов. Со страницы агента — «Подробно →».

**ОПО-5.7 · Трасса задачи** · M · ИИ · ✅ готово (решения Дирижёра — с 15.3)
- Каждый шаг агента — одной лентой: запросы к моделям (уровень, настоящая модель, кто спросил — главная модель,
  исполнитель, сжатие, зрение; токены, из кэша, цена, время, ошибка) и вызовы MCP, действия в хабе и хранилище.
  Шаги одной задачи доски (`X-SYSAI-Task`) или идущие подряд (перерыв меньше 15 минут) — один запуск.
- Пишутся и отказы шлюза (доступ, бюджет, сбой OpenRouter, оборванный поток) — с причиной и временем, без цены.
  Кто спросил — метка `sysai.role` в теле запроса: её ставят настройки Hermes (`delegation.request_overrides`,
  `auxiliary.*.extra_body`), шлюз её снимает.
- «Режим отладки» агента (владелец или администратор, видно в журнале): сохраняет конец каждого запроса к модели и
  её ответ, аргументы и результат каждого вызова MCP; сам выключается через 24 часа, тексты хранятся 7 дней. Без
  него — только числа и аргументы до 200 знаков.
- Страница агента → «Трасса»: последние запуски, где ушли токены, где ошибка; вся трасса — `/agents/{id}/trace`
  (сутки, 3 или 7 дней, только с ошибками).
- Заодно: запросы к шлюзу и MCP ждут в потоках — долгий ответ модели больше не держит остальной сервер.

**ОПО-5.8 · Jev: модель под запрос** · S · ИИ · ✅ готово (уровень задачи от Дирижёра — с 15.3)
- Jev (TypeSafe) — быстрая модель решений: не пишет текст, отвечает на типизированные вопросы (выбор из списка,
  оценка, «да/нет» с вероятностью). Есть в OpenRouter, тем же ключом SYSAI: Jev Router (`typesafe/jev-router` —
  выбирает модель и силу рассуждения под запрос) и Decisions API.
- Уровень `sysai/auto`: Jev Router с `cost_tier` из профиля («экономнее», «поровну», «сильнее»), моделями остальных
  разрешённых уровней в `models` и всеми моделями каталога OpenRouter дороже самой дорогой из них в
  `excluded_models` (`models` у Jev — только предпочтение, жёсткий запрет — `excluded_models`; каталог — раз в 12 ч).
  Настоящая модель из ответа — в учёт и трассу. Jev не ответил (400/404/5xx) — тот же запрос на `mid` (нет — `cheap`);
  на 404/503 Jev отдыхает 10 минут. Бюджет токенов рассуждения Jev не принимает — шлюз оставляет только силу.
- Встроенные профили «Инженер ОПО», «Руководитель ОПО», «ТО»: главная модель — `sysai/auto`, исполнители —
  `sysai/cheap`. Уже созданные профили не меняются: `sysai/auto` отмечают в «Доступы → Нейронки».
- Дальше (15.3): запрос по задаче доски — уровень задачи, его выбрал Дирижёр.
- Всё на сервере: на ПК ни плагинов, ни ключей. Для сжатия контекста и картинок Jev не берём — у Hermes они на
  уровнях со своей моделью (`sysai/cheap`, `sysai/vision`), и по их же замеру (сентябрь 2026) своё сжатие лучше:
  78,9 % памяти при 55 тыс. токенов против 75,5 % при 115 тыс. у Jev.

### Этап 6. Агент на ПК: обвязка, установка, синхронизация

**ОПО-6.1 · Hermes или OpenClaw** · M · ИИ

**ОПО-6.2 · Установщик** · M · ИИ · ✅ код готов — проверить на чистом Windows-ПК
- Одна строка PowerShell со страницы агента («Получить код подключения»):
  `$env:SYSAI_CODE='КОД'; irm <SYSAI>/agents/api/install.ps1 | iex` — обычный PowerShell, без администратора,
  Windows PowerShell 5.1 и новее. Скрипт — `agents/installer/install.ps1`, SYSAI подставляет свой адрес и версию.
- Ставит uv (Astral), синхронизатор (`uv tool install` колеса `/agents/api/sync/sysai_agent-<версия>-py3-none-any.whl`,
  его SYSAI собирает из `agents/sync`, Python 3.12 uv ставит сам), меняет код на токен, ставит Hermes (под Windows
  без WSL, его установщик с `-NonInteractive`), если его нет; профиль Hermes по имени агента; первая синхронизация;
  фоновая синхронизация при входе в Windows (`HKCU\…\Run`, без окна) и сразу.
- Профиль без встроенных навыков Hermes (`hermes profile create opo-<логин> --no-skills`): их 44 (Apple, музыка,
  видео, соцсети…), ОПО они не нужны, а их список уходит в каждый запрос (~3 тыс. токенов). Нужные из них — через
  SYSAI_Hub (этап 13).
- Не служба Windows, а запуск при входе: служба работает под другой учётной записью и не видит ни профиль Hermes
  человека, ни его хранилище Windows с токеном.
- Повторный запуск с новым кодом ничего не ломает: останавливает синхронизатор, обновляет его, применяет заново.
- plc-kit, machine-expert, cad приходят инструментами SYSAI_Hub (этапы 7–11), а не установщиком.
- **Готово:** чистый Windows-ПК → работающий агент за 15 минут.

**ОПО-6.3 · Синхронизатор** · M · ИИ · ✅ готово (на Windows — проверить с 6.2)
- `agents/sync` (`sysai-agent`): раз в 5 минут пульс (версии, ревизии, ошибки); сменилась ревизия доступов или хаба
  (или прошёл час) — синхронизация: подписанные доступы (проверка Ed25519), настройки Hermes, `SOUL.md`, навыки и
  инструменты SYSAI_Hub, отправка предложений. Всё применяется само, ошибки — в пульс и на страницу агента.
- Настройки Hermes: в `config.yaml` профиля меняет только свои ключи (модель, исполнители, сжатие и зрение,
  MCP, подтверждения, навыки, память…), остальное человека не трогает; прежний файл — `config.before-sysai.yaml`.
  Токен — в `.env` профиля (`SYSAI_AGENT_TOKEN`), Hermes подставляет его в `${SYSAI_AGENT_TOKEN}`. Шлюз Hermes
  запущен — перезапускает (`hermes -p <агент> gateway restart`), разговор в терминале подхватит в новом сеансе.
- Навыки хаба — в `%LOCALAPPDATA%\SYSAI\hub`, инструменты — в `…\SYSAI\tools`, только для чтения, со сверкой
  sha256; у инструмента с `requirements.txt` — своё окружение (uv). Убрали из хаба — удаляет. Навык с тем же именем в профиле — конфликт
  на странице агента, хабовый не ставится. Предложения — из `%LOCALAPPDATA%\SYSAI\proposals`.
- MCP-серверы хаба Hermes запускает через `sysai-agent mcp <имя>`: обёртка сверяет подписанный `access.json`,
  скрывает и не пропускает запрещённые инструменты, команды, папки и сайты.
- Токен — в хранилище Windows (Credential Manager), ключ подписи — с сервера при подключении. `sysai-agent status`
  — что на ПК, `sysai-agent sync` — сейчас, `sysai-agent stop` — остановить фон. Журнал —
  `%LOCALAPPDATA%\SYSAI\logs\sync.log`.

**ОПО-6.4 · Характер агента** · S · ИИ + ОПО · ✅ готово (тексты — на вычитку ОПО)

## 6. Риски

| Риск | Что делаем |
|---|---|
| Агент работает без подтверждений | доступы из настроек, запрещённые команды, жёсткий запрет обвязки, проверки в самих MCP, нет доступа к реальным ПЛК, журнал; для строгих мест — отдельная учётная запись Windows |
| Скрипты агента обходят запреты команд | права на папки и программы — на уровне Windows и в MCP-инструментах, а не только в обвязке |
| Навык из хаба ошибочен — ошибаются все агенты | утверждение владельцем, проверка перед публикацией, откат одной кнопкой, статистика правок |
| Обвязка меняется или ломается | навыки в открытом формате, умения — в наших MCP; переезд на другую обвязку без переделки |
| Чертежи разного качества | начинаем с самых частых по образцам; неясное — в вопросы |
| Machine Expert не всё умеет скриптами | проверяем первым делом (11.2); запасные пути — автоматизация окон и 11.6 |
| Логика из ТЗ ошибочна | ссылки на пункты ТЗ, испытания, лист проверки; защиты — только руками |
| Секретность чертежей | ответ на вопрос 8: ограничения по проектам, при необходимости — без облачных моделей |
