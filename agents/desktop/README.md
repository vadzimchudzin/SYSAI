# Окно «Агент SYSAI» — разговор с агентом на ПК сотрудника

Приложение Electron: разговор с Hermes этого ПК (ACP, `hermes -p <профиль> acp`) с видимыми действиями агента,
вопросами и разрешениями, остановкой и списком разговоров; справа — просмотр файлов (Word, Excel, CSV, PDF, картинки,
видео и звук, текст и код, HTML — без скриптов), холст проекта EasyBuilder Pro, проводник ПК и Хранилище SYSAI. Ничего не грузит из сети: шрифты и
библиотеки — в сборке ([LICENSES.md](LICENSES.md)).

## Как попадает на ПК

SYSAI собирает zip из этой папки сам (`app/net/desktop.py`, без `test/` и этого файла) и отдаёт по
`GET /agents/api/desktop/sysai-desktop-<версия>.zip`; sha256 сборки и выпуск Electron (версия, sha256, адреса) — в
подписанном документе агента (`desktop`). Синхронизатор (`sysai-agent desktop`, `agents/sync/sysai_agent/desktop.py`)
скачивает Electron — сначала копию SYSAI (`/agents/api/desktop/electron/<файл>`), иначе с адресов выпуска, —
сверяет оба с подписанными sha256 и кладёт в `%LOCALAPPDATA%\SYSAI\desktop`:

- `electron-<версия>\` — Electron; `app-<версия>-<sha>\` — эта папка; `desktop.json` — что окну знать от
  синхронизатора (Hermes, `sysai-agentw`, профиль, человек); `sysai.ico`;
- `data\` — данные Chromium, `cache\` — файлы Хранилища и вставки, `bridge.json` — мост для агента (пока окно
  открыто), `shortcuts.json` — что сделали ярлыки; журнал — `..\logs\desktop.log`.

Ярлыки «Агент SYSAI» (рабочий стол, «Пуск») пишет само окно: `electron.exe <app> --sysai-shortcuts`; они запускают
`sysai-agentw desktop` — открывается установленная сейчас версия. Новая сборка ставится рядом (с «обновлять сами» —
синхронизатор в фоне), открытое окно работает на своей, следующий запуск — на новой.

## Правки без вопросов

Hermes спрашивает человека перед каждой записью файла (`write_file`, `patch`): карточка «Агенту нужно разрешение», ответ
на один раз. Кнопка справа от скрепки — «Правки: спрашивать / без вопросов» (Ctrl+Shift+A) — разрешает окну отвечать
самому (`lib/autoapprove.js`, ответ «один раз»). Сам окно отвечает только на правку файлов внутри папки проекта
(`Документы\SYSAI Проекты\<проект>\…`), которую подписанные доступы SYSAI открывают агенту на запись. По-прежнему
спрашивают, и карточка говорит почему: файлы вне проектов, исходные материалы (`materials/`), секреты и служебное
(`.env`, ключи, `.git`, `.ssh`), удаление и перенос, текст больше 1 МБ, ссылка, ведущая из папки проектов, больше 300
правок за час, команды и вопросы агента. Выключено, пока человек не включит; состояние — в
`desktop\autoapprove.json`, переживает перезапуск. Перед ответом старый файл копируется в
`desktop\audit\undo\<день>\` (хранится 30 дней), каждая такая правка — строка в `desktop\audit\<год-месяц>.jsonl`;
папку SYSAI агент не пишет. Не удалась копия или запись в журнал — спрашивают человека.

**Один проект, предел профиля, «Вернуть».** В меню кнопки «Правки»: «Без вопросов · <проект>» — только в папке
проекта открытого разговора; «Без вопросов во всех проектах»; «Вернуть правку» — последние правки без вопроса, каждая
возвращается из копии (созданный ею файл убирается в журнал, ничего не удаляется). Насколько далеко кнопка может
идти, говорит профиль доступов SYSAI (`rules.edits.auto`: `off` / `project` / `projects`).

## Проекты

Вкладка «Проекты» (`lib/projects.js`, `renderer/js/projects.js`): папка на проект в `Документы\SYSAI Проекты` —
`materials/`, `plc/`, `hmi/`, `docs/`, `_work/`, `project.md`, `style.md`, `pipeline.json`.

**В папках результата — только результат.** `plc/` — проект Machine Expert (`.project`), `hmi/` — проект панели
(`.cmtp`, `.emtp`), `docs/` — документы (`.docx`, `.pdf`); всё по дороге к ним (исходники ST, шаблоны, таблицы, скрипты,
заметки, картинки) агент держит в `_work/` — так велят навыки, и `plc_stage_update` называет лишнее. Окно показывает
«Результат» отдельно, `_work` — одной свёрнутой строкой с числом файлов и размером, а если среди результатов лежат
черновики — плашку «Лишнее в plc, hmi: N» с кнопкой «Убрать в _work»: файлы переносятся (не удаляются) в
`_work/<та же папка>/`, занятое имя получает « (2)». Программа, лежащая прямо в `plc/` (`*.st`, `project.json` — раскладка
до `_work`), уходит в `_work/st/`, откуда её собирает `plc_project_build`, — если там ещё нет своей. Служебные файлы
Machine Expert и EasyBuilder рядом с проектом (`.~u`, `.opt`, `.precompilecache`, `.bootinfo`, `.compileinfo`, `.backup`,
`.bak`) не лишние и не переносятся — список один с `plcstage.py`, тест сверяет.

**Для чего каждый материал.** `<проект>/.sysai/sources.json` — запись на каждый файл и папку, лежащие прямо в
`materials/`: роль (`material` — ТЗ и схемы, `template` — шаблон проекта, `example` — образец стиля, `picture-library` —
картинки), откуда взят (`local` / `storage` с путём и версией в Хранилище), sha256 и размер. Роль ставится плашкой у
файла в «Проектах»; кнопки проекта называют агенту шаблон, пример и библиотеку картинок в самом запросе. **Добавить из
Хранилища:** кнопка с архивом в проекте открывает Хранилище, у файла или папки — «В материалы проекта»: файл берётся
через кэш окна (sha256 сверяется), папка — целиком, до 3000 файлов. Положенное в `materials/` руками получает роль по
виду файла, пока её не назвали. Индексы П4–П5 читают этот же файл.

**Разговоры по проектам.** Кнопки проекта (этап, «Создать проект», «Документация») открывают новый разговор в папке
проекта (ACP `cwd`) и кладут запрос в поле ввода: один этап — один разговор. Состояние работы — в `project.md` и
`pipeline.json`, а разговор, начатый заново, стоит в разы меньше того, что несёт все прежние этапы. В списке слева у
таких разговоров метка проекта, поиск находит по ней; «Новый разговор» из разговора проекта остаётся в проекте. При
запуске окно открывает последний разговор, а не пустой (список разговоров ждёт не дольше 4 секунд); набранный и неотправленный текст переживает перезапуск. Над проектом — полоса этапов
(материалы, решения, программа ПЛК, компиляция, экраны, документы): её пишет агент инструментом `plc_stage_update`
(plc-kit), окно каждые 4 секунды сверяет папку и перерисовывает проект, если что-то изменилось. Кнопки кладут в поле
сообщения готовую просьбу: «Создать проект» / «Продолжить: …» (все этапы по навыку `plc-project`), шаг полосы (один
этап), «Разобрать пример» (готовый проект → стиль), «Создать документацию» (появляется, когда экраны готовы; навык
`project-docs`). Список этапов в окне и в `hub/seed/plc-kit/plcstage.py` один — тест сверяет.

## Агент и окно

Каждому разговору окно даёт MCP-сервер `window` (`lib/uimcp.js` — тот же `electron.exe` как Node,
`ELECTRON_RUN_AS_NODE=1`): `show_file` (показать файл в окне), `open_file` (открыть в программе, запустить
программу), `show_in_folder`. Вызовы идут в окно через мост (127.0.0.1, токен из `bridge.json`), и окно проверяет
их по подписанным доступам (`lib/rules.js` — те же проверки, что у синхронизатора): показать — нужна папка на
чтение; программа — ещё «Команды на ПК» и ни одного запрещённого шаблона; папку SYSAI и настройки агента окно агенту
не открывает. Что делает сам человек в окне — его право, это не проверяется.

## Холст

Вкладка «Холст» — проект EasyBuilder Pro (.cmtp/.emtp) таким, каким окно проекта будет на панели: объекты, подписи
шрифтом панели (Droid Sans), картинки состояний; сверху — выбор окна, масштаб, «Отменить», кнопка «EasyBuilder»
(открыть файл в EasyBuilder Pro: программа для .cmtp, иначе найденная или выбранная — запоминается). На холсте видны
курсоры агента и его помощников — с именем и короткой репликой. Человек правит сам: щелчок, Shift, рамка — выделить;
перетащить или стрелки — сдвиг; двойной щелчок, Enter, F2 — текст; Ctrl+D — копия рядом; Delete — удалить; Ctrl+Z —
отменить; Ctrl+A — всё; 0, 1, +, − и Ctrl+колесо — масштаб; правая кнопка — «Изменить текст», «Копия рядом»,
«Удалить», «Спросить агента».

Холст работает инструментом ebpro-cmtp из хаба (`tools\ebpro-cmtp`, `lib/canvas.js`) на Python синхронизатора
(`python` в `desktop.json`). Каждая правка — сразу в файл (`cmtp_edit` поверх него), по очереди, с копией для
«Отменить» (8 шагов, `cache\canvas\undo`); файл, изменённый снаружи (EasyBuilder), перечитывается. Агенту сервер
`window` даёт `canvas_open` (открыть проект на холсте — нужна папка на чтение), `canvas_look` (окно, объекты, куда
показывает и что выделил человек, курсоры), `canvas_window` (другое окно проекта), `canvas_cursor` (подвести курсор,
сказать) и `canvas_edit` (те же правки, что `cmtp_edit`: тексты, сдвиг, размер, теги, копии и удаление окон и
объектов, кнопки на окна, новые теги, оформление фигур и подписей, привязка существующего слота OPC UA, окна и объекты из проекта-донора — нужна папка на запись; курсор идёт к
объекту); `who` — чей курсор: «Агент» или имя помощника. Удалили окно, что на холсте, — показывается следующее;
взяли окно из донора или скопировали — показывается новое.

Холст — третий из режимов сборки проекта (навык хаба `ebpro-project`): 1) агенты собирают проект без EasyBuilder
инструментом ebpro-cmtp (и вариантами на копиях); 2) агенты работают в самом EasyBuilder (инструмент `ebpro-gui`);
3) человек и агенты вместе на холсте.

## Разработка и проверки

`node --test test/unit.test.js` — части главного процесса без Electron (файлы, настройки, ACP с поддельным Hermes
`test/fake-hermes.js`, мост, MCP-сервер, доступы, Хранилище, холст с поддельным ebpro-cmtp `test/fake-cmtp.js`);
`tests/test_desktop.py` запускает их тоже и сверяет `lib/rules.js` с `sysai_agent/rules.py` и `hook.py` на одних и тех
же случаях; `tests/test_hub_seed_ebpro.py` гоняет холст с настоящим ebpro-cmtp. Запуск у себя: `electron <эта папка>`
с `SYSAI_HOME`, где есть `agent.json`, `desktop/desktop.json` и подписанный `access.json`.
