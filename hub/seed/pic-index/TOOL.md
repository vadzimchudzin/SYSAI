# Картинки оборудования для экранов

Библиотека картинок — папка с файлами PNG, BMP, JPEG, GIF и SVG (вложенные папки тоже): нории, конвейеры, шнеки,
вентиляторы, задвижки, насосы, силосы, лампы, трубы, стрелки. Обычно у механизма несколько картинок: выключен, работает,
авария, ручной режим; открыто и закрыто; влево и вправо.

Инструмент строит по папке индекс `pic-index.json` (лежит в той же папке): у каждой картинки — формат, размер,
оборудование, состояние, положение и набор, в который она входит. Дальше агент спрашивает «нория, состояния off / on /
alarm» и получает набор одним вызовом, а не перебирает файлы.

## Когда применять

- Подобрать картинки для объекта экрана: `pics_find` → `states` (состояние → файл).
- Спланировать экраны: что в библиотеке есть и какого размера — `pics_list`.
- Принять новую библиотеку или пополнение: `pics_index_update` → `pics_check` → подписать нераспознанное.
- Подписать картинку, имя которой ничего не говорит (`img0042.png`): `pics_label_update`.

## Как запускать

Синхронизатор ставит папку в `%SYSAI_HOME%\tools\pic-index` и запускает `python server.py` на своём Python (только
стандартная библиотека, ничего не скачивается, в сеть инструмент не ходит). Доступ к папкам проверяет SYSAI:
`pics_index_update` и `pics_label_update` пишут `pic-index.json` — папка с картинками должна быть открыта агенту на
запись. `pics_find`, `pics_list` и `pics_check` сами обновляют индекс, если папка изменилась; если записать файл
нельзя, работают с индексом в памяти.

Порядок: `pics_index_update` (один раз и после пополнения) → `pics_list` → `pics_find` по каждому механизму.

## Что умеет

| Инструмент | Что даёт |
|---|---|
| `pics_index_update` | обходит папку, обновляет индекс: сколько всего, добавлено, изменено, перемещено, удалено, сколько наборов, первые 50 нераспознанных; `full` — перечитать все файлы |
| `pics_find` | наборы по запросу, лучшие первыми: `equipment`, `base`, `folder`, `size`, `states`, `files`, `note`; `state` — только наборы с этими состояниями |
| `pics_list` | виды оборудования с числом наборов и картинок, список наборов, `unlabeled` — сколько картинок не распознано |
| `pics_label_update` | ручная подпись картинки: оборудование, состояние, положение, набор, заметка; пустая строка стирает поле |
| `pics_check` | чего не хватает в наборах, разные размеры, одинаковые, нераспознанные и тяжёлые картинки |

Поиск понимает русское и латинское написание («нория» = `noria` = `noriya`), падежи («нории», «задвижку») и синонимы:
нория — элеватор — elevator; конвейер — транспортёр — conveyor — belt — лента; шнек — screw — auger; вентилятор — fan;
задвижка — gate — slide — шибер; клапан — valve; насос — pump; двигатель — мотор — motor; силос — бункер — silo —
hopper; сирена — звонок; лампа — индикатор. Состояние или положение в запросе («задвижка открыта», «шнек влево»)
поднимает наборы, где оно есть. Словари — константы `EQUIPMENT`, `STATE_WORDS`, `COLOR_STATES`, `ORIENTATION_WORDS` в
начале `picindex.py`.

Состояния: `off`, `on`, `alarm`, `manual`, `warning`, `open`, `closed`, `opening`, `closing`, `unknown`.
Положения: `left`, `right`, `up`, `down`, `horizontal`, `vertical`.

## Как называть картинки

Лучше всего индексируется `<оборудование>_<вид>_<состояние>.png`, слова через `_`, `-` или пробел:

```
noria_big_off.png      noria_big_on.png      noria_big_alarm.png      noria_big_man.png
задвижка_откр.png      задвижка_закр.png     задвижка_авария.png
шнек_влево_выкл.png    шнек_влево_вкл.png    шнек_вправо_выкл.png     шнек_вправо_вкл.png
conveyors/belt_0.png   conveyors/belt_1.png  conveyors/belt_2.png
```

- **Набор** — картинки одной папки, у которых имя без состояния, положения и номеров совпадает (`noria_big`).
- **Состояние** — слово в имени: `on`, `run`, `вкл`, `работа` → on; `off`, `stop`, `выкл`, `стоп` → off; `alarm`,
  `err`, `fault`, `avar`, `авария` → alarm; `man`, `ручн` → manual; `open`, `откр` / `closed`, `закр`. Цвет тоже
  считается: `green`, `зел` → on; `red`, `красн` → alarm; `gray`, `сер` → off; `yellow`, `желт` → warning.
- **Номера** `_0`, `_1`, `_2` без слова состояния читаются как off, on, alarm — только когда в наборе есть такие
  соседи; это догадка (`state_guess`), `pics_check` о ней напомнит.
- **Варианты**: `noria1_on`, `noria1_off`, `noria2_on`, `noria2_off` — два набора, `noria_1` и `noria_2`.
- **Положение**: `left`, `right`, `up`, `down`, `лев`, `прав`, `влево`, `вправо`, `верх`, `низ`, `гор`, `верт`.
- Оборудование берётся из имени, а если там его нет — из имени папки (`noria/big_on.png`).
- `NoriaBigOn.png` и `noria2on.png` тоже читаются: слова делятся по заглавным буквам и на границе букв и цифр.

## Связь с экранами

`states` из `pics_find` — готовая таблица «состояние → файл» для картинки с состояниями в ebpro-cmtp: файл `off` —
состояние 0, `on` — 1, `alarm` — 2, дальше по проекту. Пути в `states` — относительно `dir`. Если у набора несколько
положений, рядом есть `by_orientation`: та же таблица для `left`, `right` и других. `size` — размер объекта на экране;
пустой `size` значит, что картинки набора разного размера.

Картинки берут из хранилища SYSAI, раздел «ОПО/Картинки», и копируют в `<проект>/_work/hmi/pictures/` (в `hmi/` — только готовый проект панели) — эту папку и
передают в `dir`. Индекс лежит там же и переезжает вместе с папкой.

## Ограничения

- Внутрь картинок инструмент не смотрит: только имена файлов и папок и ручные подписи. Картинку без распознанного
  оборудования агент должен посмотреть сам и подписать `pics_label_update`.
- Подпись привязана к содержимому файла: переименование и перенос её сохраняют, перерисованная картинка — новая.
- Из файла читаются только формат и размер; SVG — по `width` / `height` / `viewBox`.
- Файлы больше 20 МБ, скрытые (с точки) и не картинки пропускаются; в индекс входит не больше 20000 картинок.
- Одно слово — один вид оборудования: в `motor_noria_on.png` распознается первое (двигатель). Исправляется подписью.

## Ошибки

- «нет папки …» — путь в `dir` не существует или это файл.
- «в папке нет картинок» — в папке и вложенных нет PNG, BMP, JPEG, GIF, SVG; проверь, что картинки скопированы.
- «нет картинки … в индексе» — `file` у `pics_label_update` не найден: путь берут из `pics_find` или `pics_list`.
- «папка … не разрешена агенту на запись» (отвечает SYSAI, не инструмент) — `file` у `pics_label_update` передан
  относительным путём с вложенной папкой (`noria/x.png`): передай полный путь, `dir` + путь из `pics_find`.
- «нет состояния …», «нет положения …» — значение не из списка; списки выше.
- «пустой запрос» — в `query` нет слов.
- «файл: …» — папку нельзя прочитать или записать индекс: проверь доступ к папке.
