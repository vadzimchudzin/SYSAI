# Проект EasyBuilder Pro целиком

Нужны инструменты: **ebpro-cmtp** (файл проекта, любой ПК), для режима 2 — **ebpro-gui** (Windows с EasyBuilder Pro).
Папки материалов и выходного файла должны быть открыты агенту в доступах SYSAI (выходная — на запись).

## Когда применять

- «Сделай экраны панели для …», «добавь норию 11 как норию 3», «собери проект по тегам ПЛК и схеме».
- Есть хотя бы один проект EasyBuilder той же линейки (пример, прошлый объект, шаблон) — с нуля файл не строится:
  собираем из окон и объектов существующих проектов.
- Для одной правки в готовом файле достаточно ebpro-cmtp напрямую; этот навык — когда окон и шагов много.

## Три режима

1. **Файл** (ebpro-cmtp, `cmtp_edit`) — основной: быстро, точно, без EasyBuilder и без экрана, можно нескольким
   агентам сразу. Тексты, сдвиг, размер, теги, копии и удаление окон и объектов, кнопки меню, новые теги,
   окна и объекты из доноров.
2. **EasyBuilder** (ebpro-gui, навык ebpro-easybuilder) — то, чего файл не умеет: новый вид объекта, свойства
   в диалоге, настройки проекта, драйверы, компиляция, офлайн-симуляция. Медленно, один ведущий на ПК.
3. **Холст** окна «Агент SYSAI» — человек и агент правят одно окно вместе: человек тащит, удаляет (Delete),
   откатывает (Ctrl+Z), агент делает те же правки `cmtp_edit` в тот же файл. Для доводки расположения.

Порядок по умолчанию: всё, что можно, — режимом 1; что нельзя — режимом 2; спорное расположение — показать
человеку на холсте.

## Как делать

1. **Материалы.** По каждому проекту-примеру: `cmtp_info` (версия EasyBuilder, `revision`), `cmtp_windows`,
   `cmtp_links` (меню: какая кнопка какое окно открывает), `cmtp_tags` (таблица OPC UA). По ПЛК — список тегов
   (экспорт OPC UA / GVL CODESYS): имя, тип, назначение. По схеме и ТЗ — какие механизмы, сколько, что на экране.
2. **План** — таблица и согласование с человеком, если ТЗ неполное:

   | окно (номер, имя) | что на нём | откуда берём | теги | куда ведут кнопки |
   |---|---|---|---|---|
   | 91 «Нория 11» | как «Нория 3» | `clone_window` 31 | GVL.*_3 → GVL.*_11 | «Назад» → 20 |

   Откуда: копия окна этого же проекта (`clone_window`), окно донора (`import_window`, навык ebpro-donor), объекты
   донора (`import_objects`), руками в EasyBuilder (ebpro-gui). Номера — свободные пропуски в `cmtp_windows`.
3. **Основа.** Шаблон — проект-пример той же версии EasyBuilder; исходник не трогаем: первая же правка пишет
   `out_file` — новый файл в выходной папке.
4. **Теги.** Недостающие теги ПЛК — `add_tags` (тип — из тех, что в проекте уже есть); имена — ровно как в ПЛК.
5. **Окна.** Партиями по окну-два: `clone_window` / `import_window` → `rename_window` → `text` (подписи),
   `tag` (перепривязка) → `move` / `resize` → `delete_object` (лишнее, с конца) → `link` (кнопки меню). Новую
   кнопку меню — `clone_object` существующей и `link` на копию.
6. **Режим 2** — только для оставшегося: открыть итог в EasyBuilder (`eb_edit`), сделать, сохранить (`ctrl+s`).
   После этого файл снова можно править `cmtp_edit` (перечитать `cmtp_windows`: EasyBuilder мог перенумеровать
   объекты).
7. **Сдача.** Черновик + короткий отчёт: окна (номер, имя, откуда), меню, новые теги, что сделано в EasyBuilder,
   что осталось человеку, какие правки ещё не проверены в EasyBuilder (см. TOOL.md ebpro-cmtp).

## Правила

- Исходники и доноры только читаем; пишем только `out_file`. Одна задача — один выходной файл (варианты — ebpro-team).
- Доноры — той же версии EasyBuilder (`revision` в `cmtp_info` одинаковый), папка донора открыта агенту.
- Номера окон 0–9 — системные, не занимать и не удалять.
- После удаления объектов индексы следующих сдвигаются — удалять с конца или перечитывать `cmtp_objects`.
- Не загружать проект в панель и не трогать пароли — это человек.
- Ошибку инструмента не обходить другим путём «вслепую»: прочитать текст ошибки (TOOL.md ebpro-cmtp, «Ошибки»),
  взять другое окно, номер или объект, либо сделать это место в EasyBuilder.

## Ошибки

- Нет примера той же версии EasyBuilder — попросить человека сохранить пример в его версии (или открыть пример
  в EasyBuilder через ebpro-gui и «Сохранить как»).
- «… not in the OPC UA tag table» — сначала `add_tags`, потом `tag`.
- «where its record ends is not known», «holds sub-objects», «defines class» — это окно или объект файлом не
  взять: другой источник или режим 2.
- `cmtp_check` показывает ошибки после сборки — исправить до сдачи; предупреждения перечислить в отчёте.
- EasyBuilder не открывает итог — сдать предыдущий рабочий шаг, описать последнюю партию правок, сообщить
  разработчику (файл и список правок).

## Проверка

- `cmtp_check` по всему проекту: ошибок 0 (за краем окна, кнопка в никуда, тега нет, текст не влезает).
- `cmtp_links`: каждое окно плана достижимо из меню, нет кнопок в удалённые окна.
- `cmtp_render` каждого нового и изменённого окна (`marks` — номера объектов) — посмотреть глазами, сравнить
  с окном-образцом.
- `cmtp_tags`: все теги плана есть, типы как в ПЛК.
- Если есть ebpro-gui: `eb_edit` итога → компиляция без ошибок (навык ebpro-easybuilder); иначе — в отчёте
  попросить инженера открыть и скомпилировать.
