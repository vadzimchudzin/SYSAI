# Проект EasyBuilder Pro командой

Нужен **ebpro-cmtp**; для работы в самом EasyBuilder — **ebpro-gui**. Ведущий — агент, который получил задачу;
помощники — агенты, которым он раздаёт части.

## Когда применять

- Окон много (десятки механизмов), и их можно делать независимо.
- Нужны варианты одного экрана (раскладка, крупность, цвета) — показать человеку и выбрать.
- Человек правит окно на холсте, а агент в это время делает остальные окна или то же окно по просьбе.

## Как делать

1. **План у ведущего** (навык ebpro-project): таблица окон, меню, теги. Каждому помощнику — свои окна и **свой
   диапазон номеров** (помощник 1 — 100–119, помощник 2 — 120–139…), чтобы при сведении номера не столкнулись.
2. **Общее — сначала, ведущим.** Теги, которые нужны всем (`add_tags`), общие окна (шапка, меню) — в базовый файл
   до раздачи. Помощники меню и общие окна не трогают.
3. **Раздача.** Помощнику: базовый файл (только читать), свой `out_file` (например `…\out\helper2.cmtp`), окна
   плана с номерами, образцы. Помощник собирает свои окна в свой файл (`clone_window`, `import_window`, `text`,
   `tag`, `move`…), проверяет `cmtp_check` и `cmtp_render` и возвращает: файл, номера и имена окон, заметки.
4. **Сведение.** Ведущий одним `cmtp_edit` пишет итог: `import_window` каждого готового окна из файлов помощников
   (они от одной базы — версия совпадает), с тем же номером; затем `link` кнопок меню на новые окна:
   ```json
   {"path": "C:\\Work\\out\\base.cmtp", "out_file": "C:\\Work\\out\\итог.cmtp", "edits": [
     {"op": "import_window", "from": "C:\\Work\\out\\helper1.cmtp", "window": "100", "number": 100},
     {"op": "import_window", "from": "C:\\Work\\out\\helper2.cmtp", "window": "120", "number": 120},
     {"op": "link", "window": "Меню", "object": 12, "to": "100"}]}
   ```
   Новые теги помощников переносятся вместе с окнами.
5. **Варианты.** Два-три помощника делают одно окно по-разному в свои файлы; ведущий показывает человеку
   `cmtp_render` каждого (рядом), лучший берёт `import_window`.
6. **Холст.** Человек правит окно на холсте окна «Агент SYSAI» — тот же файл на месте. Агент, который правит
   этот файл, сначала заново читает `cmtp_objects` (человек мог удалить или сдвинуть объекты — индексы другие),
   правки делает небольшими партиями; каждая правка видна человеку и откатывается его Ctrl+Z.
7. **Один EasyBuilder.** Мышь и клавиатура одни: в EasyBuilder одновременно ведёт один (`who` в ebpro-gui);
   остальные в это время работают с файлами. Закончил — `eb_free`.

## Правила

- Один файл — один писатель в каждый момент: `cmtp_edit` ставит замок на `out_file`, но правки двух агентов
  в один файл всё равно перемешаются — у каждого свой `out_file`, итог пишет только ведущий.
- Помощники не меняют базовый файл, меню и чужие номера окон.
- Итог собирается из проверенных файлов помощников; файл с ошибками `cmtp_check` не сводить — вернуть помощнику.

## Ошибки

- «проект сейчас пишет другой агент или холст» — подождать и повторить; если повторяется — кто-то пишет тот же
  `out_file`: развести файлы.
- «window number … is taken» при сведении — номера помощников пересеклись: взять номер из пропусков
  `cmtp_windows` итога и поправить `link`.
- «EasyBuilder сейчас ведёт …» — подождать или работать с файлом; не отнимать у другого агента.
- Помощник вернул окно не того вида — показать `cmtp_render` и вернуть с замечаниями, а не переделывать молча.

## Проверка

- `cmtp_windows` итога: все окна плана на своих номерах, нет лишних копий.
- `cmtp_links`: меню ведёт в каждое окно помощников; нет кнопок в никуда.
- `cmtp_check` итога без ошибок; `cmtp_render` каждого сведённого окна совпадает с тем, что сдал помощник.
- В отчёте: кто что делал, какой вариант выбран и почему.
