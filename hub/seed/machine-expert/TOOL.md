# Machine Expert: проект, компиляция, контроллер

Файл `.project` пишет сам Machine Expert — не этот инструмент. Инструмент составляет задание, запускает Machine
Expert без окна со скриптом `me_job.py` (Python внутри программы, тот же интерфейс, что у CODESYS V3.5) и читает
результат. Так файл получается настоящим: его открывает, компилирует и загружает та же программа, которой работает
инженер.

**Файл `.project` теперь читает и пишет plc-kit — без Machine Expert** (`plc_info`, `plc_export_st`,
`plc_project_build`: новый проект из папки ST и шаблона). Этот инструмент нужен для того, что делает только сама
программа: компиляция (`me_build`), симуляция и контроллер (`me_online`, `me_scan`), проект по модели контроллера
без шаблона (`me_create`), файлы с паролем (`me_export`).

**Не проверено на живом Machine Expert.** Скрипт написан по описанию скриптового интерфейса CODESYS V3.5 и проверен
в тестах на подставной программе (`tests/fake_machine_expert.py`): проверена логика инструмента, но не сам Machine
Expert. Первые запуски — при инженере; что не сработало, инструмент называет прямо (раздел «Ошибки»).

## Когда применять

- Файл `.project` собран (`plc_project_build`, plc-kit) — нужна настоящая компиляция: `me_build` `{file, src_dir}`.
- Шаблона с контроллером нет — проект по модели контроллера из репозитория: `me_create`.
- Исправить ошибки компилятора: `me_create` / `me_update` возвращают их с файлом `.st` и строкой.
- Дали готовый `.project`, а экспорта нет (или файл закрытый): `me_export` достаёт программу папкой ST.
- Проверить без оборудования: `me_online` с `simulation` — загрузка в симуляцию, чтение и запись переменных.
- Инженер просит загрузить в контроллер или посмотреть значения: `me_scan`, `me_online`.

## Как запускать

Синхронизатор ставит папку в `%SYSAI_HOME%\tools\machine-expert` и запускает `python server.py` (только стандартная
библиотека, в сеть инструмент не ходит). Machine Expert ищется сам:
`C:\Program Files\Schneider Electric\EcoStruxure Machine Expert\<версия>\` — `LogicBuilderShell.exe` (консоль для
скриптов), затем `LogicBuilder.exe --runscript=… --noUI`, затем CODESYS. Способы пробуются по очереди, пока один не
оставит результат. Если программа стоит в другом месте — переменная `SYSAI_ME_EXE` (путь к программе); если она
принимает скрипты иначе — `SYSAI_ME_CMD` (вся команда: `"{exe}" --runscript="{script}" --noUI`).

Запуск Machine Expert долгий (минуты): по умолчанию ждём 900 с (`timeout_s`). Одновременно идёт одно задание.
Задания, результаты и вывод программы — в `%LOCALAPPDATA%\SYSAI\machine-expert\jobs` (последние 40).

## Что умеет

| Инструмент | Что делает |
|---|---|
| `me_find` | какие Machine Expert / CODESYS установлены, чем запускаются скрипты |
| `me_devices` | контроллеры репозитория устройств по части имени: имя, версия |
| `me_create` | новый `.project` из папки ST: объекты, задачи, символы OPC UA, компиляция |
| `me_update` | записать изменённые `.st` в существующий `.project` и скомпилировать |
| `me_build` | только компиляция: ошибки и предупреждения |
| `me_export` | программа из `.project` → папка ST (`out_dir`) или PLCopen XML (`out_file`) |
| `me_scan` | контроллеры в сети: имя узла, тип, адрес |
| `me_online` | вход в контроллер или симуляцию: загрузка, пуск/стоп, чтение и запись переменных |
| `me_open` | открыть проект в окне Machine Expert инженеру |

## Проект с нуля

```
_work/st/            папка ST: project.json + *.st      (пишет агент, проверяет plc-kit: plc_check)
plc/Line.project     проект Machine Expert              (me_create) — единственный файл в plc/
```

1. `plc_check` (plc-kit) — ноль ошибок.
2. `me_create` `{src_dir, out_file, template_file | controller}`:
   - **`template_file`** — шаблон проекта компании (`.project`, где контроллер, модули TM3, библиотеки и сеть уже
     настроены). Так надёжнее: конфигурацию модулей скрипт не создаёт.
   - **`controller`** — модель из репозитория (`TM241CE40R`; точное имя — `me_devices`). Берётся новейшая версия
     описания. Модулей ввода-вывода в таком проекте нет: их добавляет инженер.
   - Порядок создания: типы → списки переменных → функции → блоки → программы. Задачи — из `project.json`
     (существующая задача с тем же именем получает период, приоритет и список программ). При
     `"link": {"kind": "opcua"}` добавляется «Конфигурация символов» с OPC UA; какие списки публикуются — задаёт
     строка `{attribute 'symbol' := 'readwrite'}` в самом списке.
3. В ответе — ошибки компилятора: `ОШИБКА Main.st:14 — C0032: …`. Строка — в файле `.st` (объявление и код
   пересчитаны). Исправь файл → `me_update` → повтори. Объекты проекта, которых нет в папке ST, не удаляются — они
   названы в ответе.
4. Ошибок нет → `plc_stage_update` (этап `build`), `me_open` — показать инженеру.

## Контроллер

- `me_online` `{file, simulation: true, read: [...]}` — без оборудования: проект загружается в симуляцию Machine
  Expert. Так проверяют, что все переменные панели существуют: дай в `read` имена из `plc_hmi_tags` — те, которых нет,
  вернутся строками «НЕТ …».
- Настоящий контроллер: `ip`, `node` (имя узла из `me_scan`) или `address`; без них — как записано в проекте.
  Чтение (`read`) входит без загрузки и ничего не меняет.
- **`download`, `start`, `stop`, `write` на настоящем контроллере требуют `confirm: true`.** Ставь его только после
  явного «загружай» от инженера в этом разговоре: это работающее оборудование, а люди рядом с ним.
- Пароль контроллера (`user`, `password`) в папке заданий не остаётся.

## Ограничения

- Только языки с текстом: ST. POU на LD / FBD / CFC скрипт не создаёт и не меняет; `me_export` пишет их объявление.
- Конфигурация устройств (модули, Modbus, Ethernet, сервер OPC UA контроллера) — в шаблоне или руками инженера.
- Методы, действия и свойства блоков из папки ST не создаются; при экспорте названы в `skipped`.
- Объекты ищутся по имени во всём приложении: два объекта с одним именем в разных папках не различаются.
- Сам файл `.project` инструмент не читает и не пишет — это делает plc-kit. Разбор формата —
  `docs/opo/MACHINE_EXPERT.md`.

## Ошибки

- «Machine Expert на этом компьютере не найден» — не установлен или стоит не в стандартной папке: `SYSAI_ME_EXE`.
- «Machine Expert не выполнил скрипт. Пробовали: …» — программа запустилась, но результата не оставила. В тексте —
  каждая попытка и хвост вывода; команду можно задать целиком в `SYSAI_ME_CMD`. Покажи текст инженеру.
- «не ответил за N с» — программа не успела (первый запуск, лицензия, вопрос в окне): повтори с большим `timeout_s`
  или открой Machine Expert руками и закрой вопросы.
- «контроллера … нет в репозитории устройств» — имя не то (`me_devices`) или нужен `template_file`.
- «в проекте нет приложения (Application)» — в шаблоне нет контроллера с приложением.
- «объект … в проекте написан не на ST» — в шаблоне есть объект с тем же именем на графическом языке.
- «Замечание: задача … не настроилась» / «Конфигурация символов не создалась» — эта версия Machine Expert не дала
  сделать это скриптом: настрой в программе руками, остальное сделано.
- «вход в контроллер не удался» — адрес, кабель, пароль; `me_scan` покажет, кого видно.
