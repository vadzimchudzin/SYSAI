# Окна и объекты из проекта-донора

Нужен инструмент **ebpro-cmtp**. Донор — любой проект EasyBuilder Pro, где уже нарисовано нужное: прошлый объект,
типовой экран механизма, меню, шапка.

## Когда применять

- «Возьми экран нории из проекта Велута», «перенеси меню и шапку из старого проекта», «сделай как в доноре».
- В собираемом проекте нет подходящего окна для `clone_window`, а в другом проекте есть.
- Нужна часть окна донора (группа кнопок, индикаторы механизма) — `import_objects`.

## Как делать

1. **Совместимость.** `cmtp_info` донора и проекта: `revision` должен совпасть (одна версия EasyBuilder). Нет —
   попросить человека открыть донор в EasyBuilder проекта и «Сохранить как», или сделать это через ebpro-gui.
   Папка донора должна быть открыта агенту в доступах SYSAI **на запись** (импорт читает донор правкой
   `cmtp_edit`, а её пути SYSAI проверяет как запись) — сам донор не меняется.
2. **Разбор донора.** `cmtp_windows`, `cmtp_links` (что открывают кнопки окна), `cmtp_objects` нужного окна,
   `cmtp_render` с `marks` — какие номера объектов брать, `cmtp_tags` — теги донора.
3. **Соответствия** (до переноса, таблицей):
   - теги: тег донора → тег проекта того же типа (`map_tags`); тег, которого в проекте нет, перенесётся из
     таблицы донора сам — если он нужен под другим именем, сначала `add_tags`, потом `map_tags`;
   - окна: куда ведут кнопки донора → окна проекта (`map_windows`, имя или номер окна донора → окно проекта);
     окна, которые берём в этом же списке правок, переназначаются сами;
   - устройства: «PLC 1» донора → «OPC UA Client» проекта (`map_devices`), если названы иначе.
4. **Перенос** одним `cmtp_edit` в `out_file`:
   ```json
   {"path": "C:\\Work\\проект.cmtp", "out_file": "C:\\Work\\out\\проект_v2.cmtp", "edits": [
     {"op": "import_window", "from": "C:\\Доноры\\велута.cmtp", "window": "Нория 3", "new": "Нория 21",
      "number": 120, "map_tags": {"GVL.NORIA_3_RUN": "GVL.NORIA_21_RUN"}, "map_windows": {"Главное": "Главное"}},
     {"op": "import_objects", "from": "C:\\Доноры\\велута.cmtp", "window": "Меню", "objects": [5, 6, 7],
      "to": "Главное", "dx": 0, "dy": 40},
     {"op": "link", "window": "Главное", "object": 40, "to": "Нория 21"}]}
   ```
   Порядок: сначала окна, на которые ссылаются другие (тогда кнопки переназначатся сами), потом меню.
5. **Доводка.** Заметки ответа: какие кнопки ведут в окна донора, которые не брали («номер оставлен»), какие
   устройства без соответствия — исправить `link` / повтором с `map_*`. Тексты и подписи под проект — `text`.

## Правила

- Ревизия: правило «та же версия EasyBuilder» не обходить — другой формат записи окна сломает проект.
- Картинки донора переносятся в библиотеку проекта; одинаковые не дублируются. Фигуры библиотеки самого
  EasyBuilder переносить не нужно.
- Каждый перенос — в новый `out_file`; если результат плохой — вернуться к предыдущему файлу.
- Не брать из донора окна 0–9 (системные) и окно-рамку (index 0) объектов.

## Ошибки

- «the donor is written by EasyBuilder … the project by …» — разные версии: пересохранить донор в версии проекта.
- «window number … is taken» — номер занят: свободные — пропуски в `cmtp_windows` проекта.
- «holds sub-objects» / «class numbering …» — объект (тренд, список, группа) файлом не перенести: в EasyBuilder
  (копировать-вставить между двумя открытыми проектами, ebpro-easybuilder) или похожий объект проекта.
- «type mismatch» в `map_tags` — тег проекта другого типа: подобрать тег того же типа.
- Доступ запрещён к папке донора — попросить человека открыть её агенту на запись.

## Проверка

- `cmtp_windows` проекта: новые окна на своих номерах и с нужными именами.
- `cmtp_links`: кнопки перенесённых окон ведут в окна проекта, нет «в никуда».
- `cmtp_tags`: нет лишних тегов донора (если должны были замениться через `map_tags`).
- `cmtp_check` без ошибок; `cmtp_render` нового окна рядом с `cmtp_render` окна донора — одинаковы, кроме
  того, что меняли.
