# Документы Word по образцу

Инженер даёт готовое руководство или паспорт (.docx) как образец. Инструмент читает, как образец устроен и оформлен,
агент пишет новый документ текстом Markdown, инструмент собирает из него файл Word в оформлении образца и проверяет
его.

Сверено: собранный файл читается обратно этим же инструментом (заголовки, таблицы, рисунки, текст сходятся), все части
архива — правильный XML, связи ведут к существующим частям; LibreOffice 24.8 открывает файл и переводит в PDF
(титульный лист, содержание, таблица, рисунок, номера страниц на месте).

**Не проверено в Microsoft Word.** До проверки давай файл инженеру как черновик: пусть откроет, согласится обновить
поля (содержание) и посмотрит титульный лист и таблицы.

## Когда применять

- Проект (программа ПЛК и экраны) готов, нужна документация: «Руководство оператора», «Технический паспорт».
- Есть образец «сделай так же»: снять с него разделы и оформление (`doc_outline`), прочитать формулировки (`doc_text`).
- Собрать .docx из текста: `doc_export`. Проверить перед сдачей: `doc_check`.

## Как запускать

Синхронизатор ставит папку в `%SYSAI_HOME%\tools\doc-kit` и запускает `python server.py` на своём Python (только
стандартная библиотека, ничего не скачивается, в сеть инструмент не ходит: адреса `schemas.openxmlformats.org`,
`schemas.microsoft.com`, `purl.org` и `w3.org` в коде — имена пространств XML, а не подключения). Доступ к папкам
проверяет SYSAI. Пишет только `doc_export` — и у него на запись проверяются все пути: `out_file`, `md_file` и
`style_from`. Поэтому текст и образец для `style_from` должны лежать в папке, открытой агенту на запись (образец
можно положить копией в папку проекта). Картинки берутся по путям из текста Markdown.

Порядок: `doc_outline` → `doc_text` (нужные разделы) → написать `.md` → `doc_export` → `doc_check`.

## Что умеет

| Инструмент | Что даёт |
|---|---|
| `doc_outline` | дерево заголовков и что в каждом разделе (абзацы, списки, таблицы с шапкой, рисунки с подписями), титульный лист, страница и поля в мм, шрифты стилей и текста, колонтитулы, заготовка `outline_md`; принимает и `.md` |
| `doc_text` | текст образца как Markdown — целиком или один раздел по номеру или названию |
| `doc_export` | Markdown → .docx: стили заголовков, нумерация, списки, таблицы, рисунки с подписями, титульный лист, содержание, номера страниц |
| `doc_check` | пустые разделы, оставшиеся заготовки, заголовки не по порядку, рисунки и таблицы без подписи, сверка разделов с образцом |

Оформление без образца: А4, поля 30 / 15 / 20 / 20 мм (левое, правое, верхнее, нижнее), Times New Roman 14 пт,
интервал 1,5, красная строка 12,5 мм, по ширине. С `style_from`: размер и поля страницы, шрифт, размер, интервал,
отступ и выравнивание текста, шрифт, размер и выравнивание заголовков 1–3 — из образца. Берётся то, чем текст образца
набран на деле (`effective` в `doc_outline`), а не только то, что записано в стилях.

## Разметка Markdown

| Пишут | Получается |
|---|---|
| `#` … `####` | заголовки 1–4 (стили Word); номер «1», «1.1» ставится сам |
| `# Приложение А {-}` | заголовок без номера. Без номера и сами: Введение, Содержание, Заключение, Аннотация, Реферат, Приложение…, Список литературы — и их подразделы |
| `# 3 Название` | номер уже написан — остаётся как есть, счёт продолжается с него |
| пустая строка | новый абзац; два пробела или `\` в конце строки, `<br>` — перенос строки |
| `**жирный**`, `*курсив*`, `` `код` `` | начертание; `_` — обычный знак (имена переменных не портятся) |
| `- пункт`, `1. пункт` | списки; вложенный уровень — отступ 2–4 пробела; нумерованный начинается с написанного числа |
| таблица с `\|` и строкой `\|---\|` | таблица с рамкой, шапка жирная и повторяется на страницах; `:-:` и `--:` — выравнивание |
| `Таблица: текст` строкой выше таблицы | подпись «Таблица N — текст» |
| `![подпись](файл.png "width=120mm")` на отдельной строке | рисунок по центру и «Рисунок N — подпись»; ширина в `mm`, `cm`, `px`, `%`; без ширины — как есть при 96 dpi, не шире поля |
| `> текст` | «Примечание — текст» |
| `---` на отдельной строке | новая страница |
| текст между строками из трёх обратных апострофов | листинг моноширинным шрифтом (код ST) |
| `<!-- … -->` | пропускается |

Картинки: PNG, JPEG, GIF, BMP; путь — от папки файла `.md` или полный; путь с пробелами — в `<…>`.

## Пример как образец

1. `doc_outline {file: образец.docx}` — разделы, оформление и `outline_md`: заголовки образца с подсказкой
   `[заполнить: 3 абзаца, таблица 5×4 (Параметр | Значение | …), 2 рисунка]` под каждым.
2. `doc_text {file, section: "3"}` — как раздел сформулирован в образце.
3. Записать `outline_md` в `.md` и заполнить для нового проекта: каждую подсказку `[заполнить: …]` заменить текстом,
   таблицами и рисунками (снимки экранов — `cmtp_render` из ebpro-cmtp, адреса — `plc_hmi_tags` из plc-kit). Если в
   образце номера заголовков набраны текстом, они уже есть в заготовке — их оставить.
4. `doc_export {md_file, out_file: Руководство.docx, style_from: образец.docx, title, subtitle, organization,
   city_year, toc: true}`.
5. `doc_check {file: Руководство.docx, outline_from: образец.docx}` — каких разделов образца нет, что осталось
   незаполненным. Исправить `.md` и собрать снова.

## Ограничения

- `.doc` (старый двоичный формат), RTF, ODT не читаются: попроси сохранить как `.docx`.
- Из образца берутся страница, шрифты и интервалы. Не переносятся: колонтитулы и рамки (штамп ГОСТ), логотипы,
  оформление титульного листа, свои стили таблиц, автонумерация заголовков Word (номера пишутся текстом).
- Не пишутся: сноски, формулы, объединённые ячейки, таблицы в таблицах, картинка внутри строки текста, обтекание,
  альбомные листы посреди книжного документа, перекрёстные ссылки. Векторные картинки (SVG, EMF) — перевести в PNG.
- При чтении: текст надписей и фигур, сноски и формулы не читаются; объединённые ячейки читаются как пустые; номера
  автонумерации заголовков не вычисляются (`heading_numbering: auto`).
- Содержание — поле Word: Word заполнит его и номера страниц при открытии (спросит об обновлении полей — «Да»). До
  этого в нём названия разделов без страниц; LibreOffice обновляет его командой «Сервис → Обновить».
- Число страниц инструмент не знает.
- В Microsoft Word собранный файл не открывался (см. выше).

## Ошибки

- «файл .doc — старый двоичный формат Word…» — открыть в Word и сохранить как `.docx`.
- «не документ Word (.docx)…», «в архиве нет word/document.xml…» — файл другого вида или повреждён.
- «нет раздела «…». Разделы: …» — `section` не найден; названия перечислены.
- «Нет картинок, файл не записан» — перечислены все пути из `.md`, по которым файла нет или это не PNG / JPEG / GIF /
  BMP; документ не пишется, пока список не пуст.
- «out_file должен кончаться на .docx», «md_file — текст Markdown…» — перепутаны поля.
- «файл … занят — закройте документ в Word и повторите» — документ открыт.
- Предупреждения `doc_export` (файл записан): уровень заголовка перескакивает, раздел пуст, в строках таблицы разное
  число ячеек (дополнены пустыми), осталась заготовка, ширина картинки больше поля, после «Таблица: …» нет таблицы.
