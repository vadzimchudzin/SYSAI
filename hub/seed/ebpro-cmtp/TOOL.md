# EasyBuilder Pro: проекты .cmtp / .emtp

Формат разобран по EasyBuilder Pro 6.10.02.300 (подпись WEINTEK LABS, INC.). Контейнер:
`u32 revision` + версия (строка MFC) + второе слово revision; у новых версий (revision ≥ 240)
дальше `u32 длина` и тело в AES-128-ECB, у старых — открытым текстом. Пересборка байт-в-байт
проверена на всех 48 проектах из комплекта EasyBuilder.

Внутри — архив MFC: окна по номерам (у каждого номера свой слот; пустой номер — 4 нулевых байта, поэтому номер
окна — не просто его порядок в файле), в окне — объекты (CPartObject — виджеты, CDrawObject — фигуры). Разбор сверен
на реальном проекте cMT (88 окон, 2517 объектов, номера окон совпали с EasyBuilder); замена текста, сдвиг,
перепривязка тегов и имена окон проверены в EasyBuilder 6.10; копии окон и объектов сверены побайтно с копиями,
которые делает сам EasyBuilder (отличия — только GUID и служебные поля, которые он пересчитывает сам).

Что ещё **не открывали в EasyBuilder** (собрано и перечитано инструментом, ждёт проверки на ПК): удаление объектов
и окон, `link`, `resize`, `add_tags`, `import_window` / `import_objects` (с картинками и тегами донора). До проверки
давай такие файлы инженеру как черновик и проси открыть их в EasyBuilder.

## Когда применять

- Разобрать присланный пример проекта: какие окна, какие объекты на них, к каким тегам ПЛК привязаны, как устроено
  меню (`cmtp_links`), как окно выглядит (`cmtp_render`).
- Пополнить память примеров: вынуть картинки, тексты, типовые окна («механизм»: заголовок, переключатели, уставки).
- Собрать проект целиком: взять шаблон, скопировать и удалить окна и объекты, поменять тексты, теги, имена окон,
  размеры, направить кнопки меню, добавить теги из ПЛК, взять готовые экраны и меню из проекта-донора; проверить
  (`cmtp_check`) и посмотреть картинки окон (`cmtp_render`).
- Режимы работы (навык `ebpro-project`): 1) сборка без EasyBuilder — этот инструмент, в том числе несколькими
  агентами на копиях (варианты); 2) агенты в настоящем EasyBuilder — инструмент `ebpro-gui`, этот — чтобы прочитать
  и проверить то, что там сохранили; 3) холст окна «Агент SYSAI» — рисует окно по `cmtp_scene` и правит файл этим же
  `cmtp_edit`.

## Как запускать

Синхронизатор ставит папку в `%SYSAI_HOME%\tools\ebpro-cmtp` и запускает `python server.py` на своём Python
(нужна только cryptography — она у синхронизатора уже есть, ничего не скачивается). Доступ к папкам проверяет SYSAI:
у `cmtp_edit` **все** пути (проект, `out_file`, донор `from`) проверяются как запись — донор положи в папку, куда
агенту можно писать (например, рядом с проектом), иначе SYSAI не пропустит вызов. `cmtp_render` и
`cmtp_extract_images` тоже пишут файлы — в разрешённую на запись папку.

Разбор примера: `cmtp_info` → `cmtp_windows` → `cmtp_objects` (по окну) → `cmtp_links` (меню) → `cmtp_tags`;
картинки — `cmtp_extract_images`; как окно выглядит — `cmtp_scene` (данные) и `cmtp_render` (PNG).
Сборка: `cmtp_edit` со списком правок → новый файл; исходник не меняется. Номера окон — из `cmtp_windows`
(`number`), номера объектов — из `cmtp_objects` (`index`) или с картинки `cmtp_render` с `marks`; после копий и
удалений смотри их заново. В конце — `cmtp_check` и `cmtp_render` изменённых окон.

## Объекты окна (cmtp_objects)

- `index` — порядок в окне (на него ссылаются правки), `kind` — вид: Window (рамка окна, всегда первый), Text, Picture,
  BitLamp, SetBit, ToggleSwitch, NumericInput, NumericDisplay, FunctionKey, ASCII, QRCode, Rect, Line; со знаком «?» —
  вид угадан; `part_XX` — вид ещё не опознан.
- `bbox` — рамка [лево, верх, право, низ] в пикселях окна; `labels` — подписи (текст, шрифт, размер, x, y);
  `texts` — прочие тексты объекта.
- `addresses` — адреса: slot 1 — чтение, 2 — запись, 3 — доп. (видимость и т. п.), 0 — прочие адреса внутри объекта;
  у тегов OPC UA — `tag` (имя) и `node`. Пустые и «0» не показываются.

## Как выглядит окно (cmtp_scene)

- `window` — номер, имя, размер и `background` (цвет фона окна); `objects` — по порядку рисования (как в EasyBuilder:
  ниже по списку — поверх).
- У фигур и текстов: `fill` (цвет заливки, `null` — без заливки), `frame` и `frame_width` (рамка); у линии `bbox` —
  её концы [x1, y1, x2, y2].
- `labels` — подписи по состояниям (0, 1, …): текст, шрифт, `size` в пунктах (в пикселях ×4/3), x, y — левый верхний
  угол текста, `color`, `align`.
- `picture` — картинки состояний из библиотеки проекта: `image` (GUID файла), `transparent` (прозрачный цвет BMP),
  `key` — имя файла в `images_dir`; `shape` — GUID фигуры из библиотеки самого EasyBuilder: её в проекте нет,
  нарисовать её точно может только EasyBuilder.
- Разобрано по проекту cMT 6.10: цвета (R G B), прозрачность BMP, размеры шрифтов сверены по рамкам 321 текста.

## Меню и переходы (cmtp_links)

Функциональные клавиши проекта: `window` и `object` — где кнопка, `action` — что делает (`window` — сменить окно,
`popup` — открыть всплывающее, `close` — закрыть всплывающее, `back` — назад, `key` — клавиша клавиатуры), `target` —
номер окна, куда ведёт (`target_name` — его имя), `labels` — подписи кнопки. По ним видно дерево меню: что открывается
с главного окна, какие окна не открывает ничто. Действие разобрано для EasyBuilder 6.08.02 и новее; у старых
проектов список может быть пустым.

## Проверка (cmtp_check)

`summary` — сколько ошибок, предупреждений, заметок; `issues` — по одной: `level`, `window`, `object`, `code`, `text`.

- error: `tag_missing` — тега объекта нет в таблице OPC UA; `link_missing` — кнопка ведёт в окно, которого нет;
  `picture_missing` — файла картинки нет в библиотеке.
- warning: `opaque_object` — границы специального объекта `part_4a` распознаны, но содержимое неизвестно; его нельзя копировать или удалять. `outside` — объект выходит за край окна (окна 0–9 EasyBuilder не проверяются); `text_fit` — подпись
  примерно шире объекта (оценка по ширине букв, ±15 %); `duplicate_name` — два окна с одним именем;
  `not_parsed` — в окне есть объекты, которые разбор не опознал (правки вставки и удаления в нём откажут).
- info: `unreachable` — в окно не ведёт ни одна кнопка (нормально для стартового окна, клавиатур, окон по событиям).

Проверка не заменяет EasyBuilder: компиляцию (Build) и проверку адресов делает только он.

## Картинка окна (cmtp_render)

PNG окна: фон, фигуры, картинки первого состояния из библиотеки проекта, подписи шрифтами системы (если шрифта
проекта нет — похожим, кириллица — через запасные шрифты). Фигуры из библиотеки самого EasyBuilder (её в проекте нет)
рисуются простыми кнопками, полями и лампами; JPEG-фото — светлой рамкой. `marks` — номер (index) в углу каждого
объекта: по картинке удобно называть объекты в правках. `scale` 0.5 для окон 1920×1080 (рисуется несколько секунд),
`show` — вернуть картинку и в ответе (до 3 МБ).

## Правки (cmtp_edit)

`edits` — список, выполняется по порядку; если одна правка не прошла — файл не пишется. `out_file` может быть тем
же файлом (так правит холст окна «Агент SYSAI»): файл пишется целиком через временный рядом и подменяется разом.
В ответе, кроме текста, — `structuredContent.results`: по правке окно, объект (у копии — её новый index), рамка.

- `{"op": "text", "window": "Нория 3", "old": "Нория 3", "new": "Нория 11"}` — любой длины; если новый текст
  длиннее, рамка объекта «Текст» расширяется вправо по ширине символов (сужения нет). `object` — только в этом объекте.
- `{"op": "move", "window": "Нория 3", "object": 5, "dx": 150, "dy": 0}` — рамка и подписи внутри неё
  (те же байты, что меняет сам EasyBuilder при перетаскивании).
- `{"op": "tag", "window": "Нория 3", "old": "VariablesRetain.OFF_DKS_3", "new": "VariablesRetain.OFF_DKS_11"}` —
  перепривязать объекты окна на другой тег OPC UA: тег должен быть в таблице проекта (`cmtp_tags`) и того же типа.
- `{"op": "rename_window", "window": "Нория 3", "new": "Нория 11"}` — имя окна в списке окон.
- `{"op": "clone_window", "window": "Нория 3", "new": "Нория 11", "number": 91}` — копия окна со всеми объектами
  (теги, тексты, картинки — как в исходном) под новым номером и именем; без `number` — следующий за последним окном,
  без `new` — то же имя. Копия получает новый GUID, как при копировании в самом EasyBuilder. Дальше правки этого
  же списка могут обращаться к копии по номеру (`"window": "91"`) — по имени, если оно не совпадает с исходным.
- `{"op": "clone_object", "window": "Нория 3", "object": 35, "to": "Нория 11", "dx": 0, "dy": 60}` — копия объекта
  (вид, теги, подписи) в конец списка объектов того же окна или окна `to`, со сдвигом; номер копии — в ответе.
  Окно-рамку (index 0) не копирует — для этого `clone_window`. Если конец записи окна-приёмника не определён
  (редко: окно, после которого в файле нет подсказки), копия встаёт перед последним объектом — номер в ответе.
- `{"op": "picture_states", "window": "Нория 3", "object": 8, "states": [{"image_file": "C:\\Projects\\stop.png"}, {"image_file": "C:\\Projects\\run.png"}, {"image_file": "C:\\Projects\\alarm.png"}]}` — заменить изображения состояний **одного** существующего объекта. Все PNG — полные пути в разрешённой папке; вместо `image_file` можно передать `image` — GUID файла из `cmtp_scene` или `cmtp_extract_images`, дополнительно `transparent: "#RRGGBB"`. Число состояний должно совпадать с исходным объектом: этот инструмент не меняет логику состояний или привязки. Использует отдельную группу картинок, остальные объекты не меняются. Собранный файл необходимо открыть и проверить в EasyBuilder; на реальное оборудование не загружать без инженерной проверки.
- `{"op": "resize", "window": "Нория 3", "object": 6, "width": 150, "height": 50}` — новый размер в пикселях, левый
  верхний угол на месте; подписи по центру и справа сдвигаются за серединой и правым краем. Картинка объекта на
  панели растянется по новой рамке.
- `{"op": "delete_object", "window": "Нория 3", "object": 34}` — удалить объект; следующие объекты окна сдвигаются
  на один index вниз — удаляй с конца (34, 33, 32) или смотри `cmtp_objects` заново.
- `{"op": "delete_window", "window": "Нория 99"}` — удалить окно, номер освобождается; номера остальных окон не
  меняются. В ответе (`links`) — кнопки, что ещё ведут в удалённое окно: перенаправь их (`link`) или удали.
  Окна 0–9 (системные EasyBuilder) не удаляются.
- `{"op": "link", "window": "Аспирация", "object": 17, "to": "Нория 11"}` — кнопка (FunctionKey, что уже меняет окно
  или открывает всплывающее) ведёт в окно `to`. Новую кнопку меню делают копией существующей (`clone_object`) и
  `link` на копию.
- `{"op": "add_tags", "tags": [{"name": "GVL.START_11", "type": "BOOL"}, {"name": "GVL.SP_11", "type": "INT",
  "node": "ns:4;s:GVL.SP_11"}]}` — добавить теги в таблицу OPC UA (в конец, перед служебным «UaStatus Code»).
  `node` по умолчанию — ns таблицы и `s:` = имя. Тип — один из тех, что в проекте уже есть (BOOL, INT, UINT, UDINT,
  REAL…): структуру записи другого типа инструмент не знает. Тот же тег второй раз пропускается. Дальше в этом же
  списке их можно ставить правкой `tag`.
- `{"op": "import_window", "from": "C:\\Projects\\donor.cmtp", "window": "Нория 3", "new": "Нория 21", "number": 120}`
  — окно донора со всеми объектами под новым номером (без `number` — после последнего окна).
- `{"op": "import_objects", "from": "C:\\Projects\\donor.cmtp", "window": "Меню", "objects": [5, 6, 7],
  "to": "Главное", "dx": 0, "dy": 40}` — объекты окна донора в конец окна `to` со сдвигом (меню, шапка, группа кнопок).

## Окна и объекты из донора

- Донор — проект, **сохранённый той же версией EasyBuilder**, что и собираемый (`cmtp_info` → одинаковый `revision`).
  Если версии разные — открой донор в том EasyBuilder, что у проекта, сохрани копию и бери её.
- Картинки объектов переносятся в библиотеку проекта; одинаковые файлы (по содержимому) не дублируются, совпавшие
  GUID получают новые. Фигуры из библиотеки самого EasyBuilder (`shape`) переносить не нужно.
- Теги: тег донора, который есть в проекте с тем же типом, остаётся; которого нет — добавляется из таблицы донора;
  `map_tags` `{"GVL.NORIA_3": "GVL.NORIA_21"}` — перепривязать при переносе (тег проекта, тот же тип).
- Кнопки: если окно, куда ведёт кнопка донора, взято в этом же списке правок, кнопка ведёт на его новый номер;
  `map_windows` `{"Нория 3": "Нория 21"}` — куда вести остальные (имя или номер окна донора → окно проекта); иначе
  номер остаётся, в заметках сказано, что там в проекте.
- Устройства (ПЛК, OPC UA) — по имени; `map_devices` `{"PLC 1": "OPC UA Client"}`, если в проекте они названы иначе;
  без соответствия — заметка.
- Объекты со вложенными объектами (тренды, списки) берутся, только если нумерация классов донора разобрана надёжно;
  иначе — отказ с пояснением, возьми их в EasyBuilder.
- После переноса — `cmtp_check` и `cmtp_render` новых окон.

## Несколько агентов и холст

- `cmtp_edit` берёт замок `<out_file>.sysai-lock` (ждёт до 20 с; замок старше 2 мин считается брошенным): два агента
  или агент и холст не испортят файл друг другу, но правки идут по очереди.
- Варианты — каждый агент пишет свою копию (`out_file` — свой файл), ведущий собирает лучшее в итоговый проект
  `import_window` / `import_objects` из копий (они той же версии).
- Холст окна «Агент SYSAI» правит тот же файл на месте (`out_file` = `path`) и откатывает правки по байтам.

## Ошибки

- «payload not 16-byte aligned» / «truncated payload» — файл повреждён или это не проект EasyBuilder.
- «no window …» — нет окна с таким именем или номером: посмотри `cmtp_windows`.
- «text … not found» / «tag … is not used» — в окне нет такого текста или тега: посмотри `cmtp_objects`.
- «is not in the OPC UA tag table» / «type mismatch» — нового тега нет в проекте или у него другой тип.
- `cmtp_relabel` требует новый текст той же длины (для текстов любой длины — `cmtp_edit`, op text).
- Копии: в архиве MFC каждый объект занимает номер, вставка сдвигает ссылки на классы дальше по файлу — инструмент
  пересчитывает их и сверяет итог; при любом расхождении правка отменяется, файл не пишется:
  - «window number … is taken» / «window numbers go from 3 to 1999» / «no free slot» — номер занят или вне
    диапазона: свободные номера — пропуски в `cmtp_windows`.
  - «cannot be placed reliably; take N» — пустые номера перед новым окном не отличить от конца предыдущего окна:
    возьми предложенный номер N (сразу за предыдущим окном) или номер в другом пропуске.
  - «not every object is recognised» — в окне есть объект, который разбор пропустил; копировать и вставлять в такое
    окно небезопасно.
  - «holds sub-objects» / «defines class» — у объекта вложенные объекты (группа, тренд и т. п.) или в нём описан
    особый класс: такие пока не копируются, возьми похожий объект из другого окна.
  - «class numbering does not add up» / «class references do not add up» — файл устроен не так, как ожидалось:
    правка отменена, пришли проект разработчику.
  - «has no frame to shift» — у объекта не найдена рамка: копируй без dx/dy.
  - «where its record ends is not known» — где кончается запись окна, по файлу не определить: копировать это окно,
    его последний объект, удалять последний объект или ставить новое окно сразу за ним небезопасно. Возьми другой
    номер окна или другой объект; вставка новых объектов в такое окно идёт перед последним объектом.
  - «inserting before the first widget / shape definition is not supported» — вставка в самое первое окно файла
    перед объектом, где описан класс виджетов: вставь в другое окно и перенеси в EasyBuilder.
- Удаление: «defines the widget class of the whole project» / «defines the widget classes» — в этом объекте (окне)
  описан класс, на который ссылаются все остальные: его удалить нельзя (удали в EasyBuilder); «belongs to
  EasyBuilder» — окна 0–9 системные.
- `link`: «is not a function key with a known action» / «does not open a window» — это не кнопка смены окна:
  возьми FunctionKey из `cmtp_links` с `action` window или popup.
- `add_tags`: «has no OPC UA tag table» — в проекте нет сервера OPC UA: добавь его и один тег в EasyBuilder;
  «type … is not used in this project yet» — тег такого типа сначала добавь один раз в EasyBuilder; «is already in
  the table as» — имя занято тегом другого типа или адреса.
- Донор: «the donor is written by EasyBuilder X (format N), the project by Y» — пересохрани донор в версии проекта;
  «may hold sub-objects and the class numbering of the donor …» — вложенные объекты не переносятся, возьми их в
  EasyBuilder; «the picture objects of the project were not recognised» — картинки не перенести, возьми окно без
  них; «tag … is not in the OPC UA tag table» / «type mismatch» в `map_tags` — тег проекта не тот.
- «проект сейчас пишет другой агент или холст — повторите через минуту» — файл занят (замок `.sysai-lock`).
- «window numbers moved» / «does not read back» — проверка после правки не сошлась: правка отменена, файл не записан;
  пришли проект разработчику.
