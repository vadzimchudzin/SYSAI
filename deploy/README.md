# SYSAI на своём сервере

Одна команда поднимает всё: Postgres, приложение, Caddy (HTTPS) и ночной бэкап. Одинаково на Linux и на Windows, через Docker.

> **Что проверено.** Разбор YAML и сверка с кодом приложения. **Что не проверено.** Сам `docker compose` и Caddy я не запускал: там, где готовились эти файлы, Docker нет. Первый запуск лучше сделать днём, не перед показом.

## 1. Что нужно

- Компьютер, который работает круглосуточно. Ассистент пишет людям и ставит напоминания, пока машина включена. Ориентир (не измерялся): 2 ядра, 4 ГБ памяти, 20 ГБ диска. Распознавание и анализ идут в облаке OpenRouter, локально работают только ffmpeg и сборка PDF.
- Выход в интернет (OpenRouter, Telegram). Входящие соединения из интернета нужны только если сайт должен открываться снаружи.
- Docker с Compose v2.

Для круглосуточной работы лучше небольшой Linux (Ubuntu 24.04 или Debian 12). На Windows всё работает через Docker Desktop, но есть оговорки (раздел 3).

## 2. Linux

1. Установите Docker Engine и плагин Compose по инструкции на docs.docker.com/engine/install (Ubuntu или Debian). Проверка: `docker compose version`.
2. `git clone https://github.com/vadzimchudzin/SYSAI.git && cd SYSAI/deploy`
3. `cp .env.example .env` и заполните файл (раздел 4).
4. `docker compose up -d --build`
5. Через минуту: `docker compose ps` (все сервисы работают, у `db` и `sysai` статус healthy) и `docker compose logs -f sysai`.

## 3. Windows

1. Нужны Windows 10 22H2 или новее (лучше 11 Pro) и включённый WSL 2. Установите Docker Desktop (docs.docker.com/desktop/setup/install/windows-install), режим WSL 2. Для малого бизнеса Docker Desktop бесплатен, для компаний больше 250 сотрудников или 10 млн долларов выручки он платный (условия на сайте Docker).
2. Установите Git для Windows. В PowerShell: `git clone https://github.com/vadzimchudzin/SYSAI.git; cd SYSAI\deploy`
3. `Copy-Item .env.example .env`, откройте в Блокноте, заполните (раздел 4), сохраните как UTF-8. Следите, чтобы имя файла осталось `.env`, а не `.env.txt`.
4. `docker compose up -d --build`

**Чтобы работало круглосуточно:**
- Электропитание: «Сон: никогда», в том числе при работе от сети.
- Docker Desktop → Settings → General → *Start Docker Desktop when you sign in to your computer*.
- Контейнеры стартуют сами (`restart: unless-stopped`), но только когда запущен Docker Desktop, а он запускается после входа пользователя в Windows. Для машины без монитора включите автоматический вход (`netplwiz`) или поставьте Linux.
- Обновления Windows перезагружают машину сами. Задайте «Активные часы», чтобы перезагрузка не пришлась на рабочий день. После перезагрузки SYSAI поднимется сам. Напоминания, которые должны были уйти во время простоя дольше 20 минут, людям не уходят, ассистент сообщает об этом тому, кто их просил.
- Если сайт нужен на других компьютерах, разрешите в брандмауэре входящие порты 80 и 443.

## 4. Файл .env

| Переменная | Что писать |
|---|---|
| `POSTGRES_PASSWORD` | Только буквы и цифры. `python3 -c "import secrets; print(secrets.token_hex(24))"` |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | Вход в кабинет. Пока пароль `SYSAI` или пустой, вход суперпользователя закрыт |
| `SECRET_KEY` | Длинная случайная строка. При переезде с Render возьмите ту же, что там (раздел 6). Пока ключ по умолчанию, вход закрыт для всех |
| `SITE_ADDRESS` | Как открывают сайт, без `https://`: IP сервера, имя в сети или домен |
| `TLS_ARG` | `internal` для офисной сети, почта для домена из интернета (раздел 5) |
| `TIMEZONE` | `Europe/Minsk` |
| `TELEGRAM_MODE` | `polling`, бот работает без публичного адреса. В режиме ИИ-сотрудника не используется |
| `OPENROUTER_API_KEY`, `TELEGRAM_BOT_TOKEN`, `BITRIX_WEBHOOK_URL` | Можно оставить пустыми и вставить в Настройках кабинета |
| `BACKUP_KEEP_DAYS` | Сколько дней хранить дампы, по умолчанию 14 |

Комментарии в `.env` только на отдельных строках. Файл не коммитится.

## 5. HTTPS

Браузер разрешает запись с микрофона только на страницах по HTTPS. Загрузка готового файла работает и без него. Caddy делает HTTPS сам, порт 8000 наружу не открыт.

**A. Сайт только внутри офисной сети.** `SITE_ADDRESS` это IP сервера (например `192.168.1.10`) или имя (`sysai.office`), `TLS_ARG=internal`. Caddy выпустит сертификат своим локальным центром. На каждом компьютере, где откроют сайт, один раз установите его корневой сертификат:

```
docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt ./caddy-root.crt
```

- Windows: двойной щелчок по файлу, «Установить сертификат», «Локальный компьютер», «Поместить все сертификаты в следующее хранилище», «Доверенные корневые центры сертификации».
- macOS: Связка ключей, добавить файл, «Всегда доверять».
- Если используете имя, а не IP, добавьте его в DNS роутера или в файл hosts каждого компьютера.

В файле `root.crt` закрытого ключа нет, его можно раздавать.

**Б. Сайт открыт из интернета по домену.** Домен указывает на внешний IP, порты 80 и 443 проброшены на сервер. `SITE_ADDRESS=sysai.example.com`, `TLS_ARG=ваша@почта`. Caddy сам получит сертификат Let's Encrypt.

## 6. Переезд с Render и Neon

Порядок важен. Аккаунт Telegram нельзя держать запущенным в двух местах, а защита от этого (аренда сессии на 90 секунд) работает только внутри одной базы. Поэтому сначала выключаем Render, потом поднимаем новое.

**Подготовка (сайт на Render ещё работает):**

1. В Render → Environment скопируйте `SECRET_KEY` и `ADMIN_PASSWORD` в `.env` нового сервера. `SECRET_KEY` должен остаться прежним: от него зависит шифрование сессии Telegram, лежащей в базе. Если ключ другой, придётся заново войти в аккаунт Telegram в Настройках.
2. В Neon → Connect выключите *Connection pooling* и скопируйте строку без `-pooler` в имени хоста.
3. Пробный запуск на пустой базе: `docker compose up -d --build`, сайт открывается, затем `docker compose stop sysai`.

**Переключение (сайт будет недоступен 10 до 20 минут):**

4. Render → сервис sysai → Settings → *Suspend Service*. С этого момента аккаунт Telegram отпущен.
5. Дамп из Neon (одна команда, работает и в bash, и в PowerShell):
   ```
   docker run --rm -v "${PWD}:/out" postgres:17-bookworm pg_dump "ПРЯМАЯ_СТРОКА_NEON" -Fc --no-owner --no-privileges -f /out/neon.dump
   ```
   Если пишет про разницу версий сервера, возьмите образ `postgres` той же версии или новее, чем у Neon (версия в Neon → Settings).
6. Восстановление в новую базу:
   ```
   docker compose up -d db
   docker compose cp neon.dump db:/tmp/neon.dump
   docker compose exec db pg_restore -U sysai -d sysai --clean --if-exists --no-owner --no-privileges /tmp/neon.dump
   ```
   Сообщения «does not exist, skipping» нормальны. Строки со словом `error` читайте внимательно.
7. `docker compose up -d`
8. Проверки из раздела 7. Аккаунт Telegram подключится в пределах 2 минут после остановки Render.
9. Откат, если что-то не так: Render → *Resume*. Neon мы только читали, она не изменилась. Только не запускайте старое и новое одновременно.

Через неделю без проблем Neon и Render можно удалить. Пароль Neon светился в чате: смените его или удалите проект.

## 7. Проверка после запуска

- `https://АДРЕС/health` показывает `"ok": true`, а через 40 секунд `"telegram_account": true`. Поле `commit` пустое: оно заполняется только на Render.
- Вход по `ADMIN_USERNAME`. Если страница пишет «Вход закрыт», в `.env` остался пароль `SYSAI` или `SECRET_KEY` по умолчанию.
- Настройки → Telegram-аккаунт: подключён.
- Новое совещание → «Демо без аудио»: вся цепочка до Telegram.
- Новое совещание → «С микрофона»: запись идёт (проверка HTTPS).
- Голосовое ассистенту: «Напомни мне через 5 минут проверить почту».

## 8. Бэкап и восстановление

Сервис `backup` раз в сутки делает дамп в папку `backups/` рядом с `compose.yaml`, первый сразу после запуска, хранит `BACKUP_KEEP_DAYS` дней. В дампах расшифровки совещаний и зашифрованная сессия Telegram: копируйте их на другой диск или в закрытое хранилище, не в общую папку. Бэкап на том же диске не спасёт от поломки диска.

Восстановление из дампа: `docker compose stop sysai`, затем шаги 6 из раздела 6 с нужным файлом из `backups/`, затем `docker compose up -d`.

## 9. Обновление и откат

```
cd SYSAI && git pull && cd deploy && docker compose up -d --build
```

Откат: `git checkout ХЭШ_КОММИТА` и снова `docker compose up -d --build`. Данные в томах при этом не меняются.

## 10. Если что-то не так

| Что видно | Что проверить |
|---|---|
| Сайт не открывается по https | `docker compose logs caddy`: `SITE_ADDRESS`, порты 80 и 443, брандмауэр |
| Браузер ругается на сертификат | Корневой сертификат не установлен (раздел 5, А) |
| «Вход закрыт» | `ADMIN_PASSWORD` не `SYSAI`, `SECRET_KEY` не по умолчанию, затем `docker compose up -d` |
| `sysai` не стартует | `docker compose logs sysai`; пароль базы с символами, ломающими адрес (нужны только буквы и цифры) |
| Telegram не подключается после переезда | Render ещё запущен, или `SECRET_KEY` другой: войдите в аккаунт заново в Настройках |
| Запись с микрофона не стартует | Страница открыта по http, а не по https |
